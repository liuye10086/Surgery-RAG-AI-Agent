# 合成病例生成器复用评估

日期：2026-09-14。状态：代码审查与本地诊断完成；未实施新生成器，未完成整条系统验收。

**结论：当前演示生成器只能保留为小规模流程冒烟样例，不能直接承担本次“用合成病例验证整个预测报告系统”的主要数据来源。建议复用来源标记、导出和验收基础设施，重新设计病例生成逻辑及场景验收。**

用户已授权先使用合成病例推进工程验证，待取得真实病例后逐步接入；随后要求先评估旧生成器。此前“可以直接复用”的表述过宽，本记录据实际检查修正该判断。真实数据审批不再是启动工程验证的前置条件；这不等于真实数据训练条件或临床性能门槛已满足。

## 1. 评估对象和方法

主要对象为 `backend/app/services/longitudinal_demonstration_data.py` 中的 `longitudinal-demonstration.v1`，入口为 `scripts/build_longitudinal_demonstration_dataset.py`。仓库现有数据快照 `dataset-6f9c8a2da687` 的 manifest 也记录该生成器版本、每病种 30 人和 `synthetic_demonstration` 用途。

本次不是对仓库全部历史生成器的统一结论。早期 `generate_*_longitudinal.py`、`extend_*_longitudinal_to_300.py` 是另一组实现；本次“扩到 300 人”的实验是调用 **demonstration.v1 的 `patients_per_disease=300`**，没有运行旧扩充脚本或读取原始病例。

执行方式：

- 使用项目 Python 3.11.4，在内存中分别生成每病种 30 人、10 次访视，共 600 行；另生成每病种 300 人检查扩量后的轨迹种类。
- 对比种子 20260827、20260914；比较时只去掉 `generator_seed` 值的差异，保留其余内容。
- 调用现有 dataset builder、患者分区和趋势标签函数。分区采用旧生成器导出流程的种子 42、18/6/6 患者划分，仅用于本次诊断；不批准新任务的正式分区。
- 计算轨迹重复、单位、缺失、时间间隔，以及只看复查次数的标签查表诊断；不拟合模型、不发布模型、不写数据库。
- 本地可重跑脚本：`.tmp/synthetic-generator-review/audit_generator.py`；仅含汇总的结果：`.tmp/synthetic-generator-review/audit-results.json`。脚本命令为 `backend/.venv/Scripts/python.exe -X utf8 .tmp/synthetic-generator-review/audit_generator.py`。这些为被 Git 忽略的本机分析材料。

## 2. 已验证问题

| 检查 | AD | 脂肪肝 | 对本次用途的影响 |
| --- | --- | --- | --- |
| 30 人的完整指标轨迹种类 | 5 | 7 | 大量患者共享完全相同的测量序列；此处不含年龄、性别和身份字段 |
| 扩到 300 人后的轨迹种类 | 仍为 5 | 仍为 7 | 加人数没有增加轨迹类型 |
| 访视次数与相邻间隔 | 每人 10 次、均隔 300 天 | 每人 10 次、均隔 300 天 | 无法覆盖稀疏、不规则、短历史等情形 |
| 种子变化是否改变日期、数值等实际内容 | 否 | 否 | `seed` 只进入元数据，不能产生不同队列 |
| 6 个测试患者中，完整指标序列在训练患者出现过的人数 | 6/6 | 6/6 | 患者 ID 分开了，指标轨迹模板仍全部重复 |
| 全部测量的单位为空 | 1500/1500 | 2100/2100 | 不适合直接测试带单位的正常病例输入和证据比较 |
| 指标值缺失 | 0 | 0 | 无法靠此批病例覆盖缺测处理 |
| 患者事件日程种类 | 1 | 1 | 同病种所有患者按同一时间表到达指定终点 |
| 标记为随访不足的固定窗口样本 | 0 | 0 | 缺少该失败／不可判定路径的生成覆盖 |
| 访视包含明确 `visit_context` | 0 | 0 | 缺少检查条件、已知时间等上下文场景 |

代码机制与统计一致：脂肪肝所有指标共用固定访视倍数，患者差异仅为七档缩放；AD 使用固定数组加五档微小偏移。300 个 AD MMSE 值中有 240 个带小数，生成器没有说明原始总分、换算分或其他计分依据。本项仅记录编码事实，不能据此宣称这些是符合某量表版本的真实测量。

所有任意两次访视间距都是 300 天的整数倍，因此精确间隔为 182、183、365、366 天的测量对均为 0。旧 builder 的任务是 365 天内事件，趋势任务是下一次访视方向；它没有构造新任务所需的 6／12 个月 MMSE、ALT 实测数值目标。这里没有选择新的随访容差，也没有把 300 天自动归入 12 个月。

### 最关键的诊断：不读取指标也能命中标签

先用训练分区建立“输入键 → 标签”的查表规则，再在测试分区计数；不读取测试标签建表、不读取任何指标值。事件键是既有任务路由加历史复查次数；单病种单指标的趋势键只有历史复查次数。

| 诊断对象 | AD 测试样本命中 | 脂肪肝测试样本命中 |
| --- | --- | --- |
| 旧事件标签 | 24/24 | 36/36 |
| 下一次 MMSE／ALT 方向标签 | 42/42 | 42/42 |

所有查表键在训练分区都只有一个标签，测试分区也没有新键。**这实证说明该批数据存在与固定访视进程绑定的标签捷径，不能把其高分解释为理解了患者指标变化。** 这些是结构诊断计数，不是正式性能结果，也没有重新估计当前已保存模型的 AUC。

同时，训练与测试的患者 ID 交集为 0；dataset builder 使用锚点之前的访视构建特征，并拒绝结局／身份等禁止字段。此次问题应表述为“模板重复和流程变量决定标签”，不能据此指控患者分区失效或未来标签字段直接泄漏。

## 3. 可以保留的部分和边界

| 部分 | 处置 |
| --- | --- |
| 旧生成器和旧模型／数据版本 | 保留原样，作为旧行为回归样例；不冒充新任务的验证数据 |
| 合成来源标记、生成器版本和导出哈希 | 复用；新版本记录真实生效的随机配置与用途 |
| 患者／依赖组隔离思路 | 复用；另检查重复模板和共享生成来源，不只检查不同 ID |
| 现有导出器 | 可复用版本和防覆盖机制；其固定 365 天事件 schema 不能直接等同于新 6／12 月数值任务 |
| 病例录入、权限、任务、历史和 PDF 验收脚本 | 复用已有实现和断言；另补本次场景，并在隔离环境实跑后才声称链路通过 |
| 旧病例轨迹生成逻辑 | 不作为本轮主生成器；单纯增加人数、扩大噪声不足以解决上述问题 |

还发现一项必须保留的隔离边界：`scripts/seed_operator_report_e2e.py` 为测试参考病例分支，有意给虚构 fixture 设置 `is_synthetic=False`，同时记录 `e2e-synthetic-*` 和 `automated_test` 来源，脚本仅允许本机 `_test` 数据库。这是既有测试分支模拟，**不能把这些种子直接导入业务库或用来宣称已有真实参考病例**。后续新验收必须区分该 fixture 覆盖与真正的来源准入。

## 4. 推荐的新生成方式

不建议给旧模板简单加随机噪声；那仍可能让时间进程或生成类别决定结果。现阶段也没有必要增加复杂生成模型或外部 LLM。推荐可审计的场景生成器，分两类用途：

1. **固定验收病例**：少量人工可核对的场景，逐个写明期望行为。覆盖正常输入、缺单位、单位冲突、缺目标、历史未知、确证零历史、同日重复、日期乱序、迟到信息，以及目标日期边界。无效输入应被拒绝或保持不可判定，不能为了全绿补值。
2. **变化充分的模拟队列**：患者分别生成初值、变化速度、转折及测量扰动，使用不同访视节奏、缺测和失访情形；包含稳定、改善、恶化轨迹。这些比例和范围作为软件测试配置，不声称代表临床人群。未来目标与锚点前可用输入分开保存；共享来源／生成依赖可追踪。

6／12 个月任务采用明确记录的工程测试时间配置，覆盖准时、提前、延迟和缺访样例；不将测试时间配置写成已批准的临床容差。量表值、单位和计分表示先遵循任务数据契约；未确定项明确标记，不自动推断。

新生成器至少需要通过以下检查：相同种子可复现；不同种子实际改变队列；增加人数不会只复制旧模板；固定病例能核对期望结果；未来记录变化不会影响锚点特征；按患者／依赖组分区无交叉；有专门保留的不同轨迹及访视机制用于挑战检查。固定冒烟样例可以简单，但模拟队列不能再把任务类别与复查次数当作标签的唯一决定因素。

这是后续实现的建议范围，**不是已完成的新生成器或已批准的临床分布设计**。

## 5. 真实病例的逐步接入

“替换”应发生在新数据版本和模型使用范围上：真实病例独立导入、核验单位和时间、记录来源和依赖组，形成新版本；按任务的真实样本支持程度开展独立评价，再替换该任务的候选模型／发布版本。默认分别统计真实与合成结果，不靠混合数据得到一个所谓正式性能值。

旧合成病例、旧报告输入快照和已归档 PDF 保留原身份，不把 `is_synthetic` 改为 False，也不使用真实数据重算后覆盖旧报告。固定合成用例可长期保留作回归测试，即使正式评价已转为真实病例。
