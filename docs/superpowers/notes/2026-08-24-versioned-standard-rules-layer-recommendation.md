# 版本化标准规则层推荐方案留痕

- 记录日期：2026-08-24
- 协作方式：简化流程
- 状态：**方案留痕，未实施**
- 目的：在移除单时点预测报告相关功能前，保留参考标准重构的架构决策，供后续规格设计使用。
- 当前范围：不改代码、不改数据库、不迁移现有数据、不删除任何功能。

## 一、推荐结论

建立独立的、版本化的标准规则层；保留现有 `reference_ranges` 作为兼容投影，而不是继续把它当作参考标准的唯一事实来源。

推荐的边界是：

1. 普通参考范围、明确比较符号的阈值、明确的分级区间和明确的组合规则，可以进入机器判定。
2. “升高/降低”、影像表现、研究发现等方向性内容，默认作为证据，不自动转成数值规则。
3. 带平台、示踪剂、年龄、队列、量表版本或研究条件的阈值，只有在适用条件完整匹配时才允许参与机器判定；否则只能作为证据展示。
4. 同一指标的多个研究阈值必须并存，禁止平均、合并或按最新写入时间任意覆盖。

## 二、当前问题留痕

当前 `reference_ranges` 只表达单条数值范围，无法表达标准文档中的完整语义：

- 脂肪肝标准同时包含指标字典、正常范围、脂肪肝分级、病理金标准、MAFLD/ALD/NAFLD 等组合或排除规则、设备限制和维度区分。
- AD 标准同时包含核心生物标志物方向、影像表现、认知/功能量表、NIA-AA 阶段框架、研究特异阈值、平台限制、A/T/N 解释规则和冲突阈值约束。
- 当前数据库中脂肪肝标准为 34 条、AD 标准为 52 条；已出现重复指标、不同语境阈值混在一起、单位被说明文字污染等问题。
- 当前上传流程复用病例文档的通用分块/向量化；标准解析又重新读取原始 DOCX，形成第二条不一致的解析路径。

因此，继续扩展 `reference_ranges` 字段或继续复用病例分块策略，不能解决标准语义丢失问题。

## 三、目标数据模型

### 1. `reference_standards`

表示逻辑标准集合，例如“脂肪肝标准”“AD 标准”。建议字段包括：

- `id`
- `disease_id`
- `name`
- `description`
- `status`
- `created_at` / `updated_at`

### 2. `reference_standard_versions`

表示一次不可变的标准版本。建议字段包括：

- `id`、`standard_id`
- `document_id`
- `version_label`
- `content_hash`
- `parser_version`
- `status`：`draft` / `review` / `approved` / `retired`
- `supersedes_version_id`
- `effective_from` / `retired_at`
- `approved_by` / `approved_at`

版本发布后不原地修改；修订必须生成新版本。

### 3. `standard_indicators`

保存规范化指标字典：

- 规范英文名和中文名
- 别名/历史名称
- 数据类型和默认单位
- 指标领域（实验室、影像、认知、功能等）
- 方向性及是否允许数值比较

病例输入、规则解析和报告展示都通过规范指标标识关联，避免只靠字符串模糊匹配。

### 4. `standard_segments`

保存标准文档的结构化解析片段：

- 章节、表格、行、列等来源位置
- 原始文本
- 片段类型：`table_row`、`paragraph`、`stage_row`、`rule_text` 等
- 页码/表号/行号等定位信息
- 解析状态和审核状态
- 可选的结构化中间结果

该表是标准解析的中间层，不复用病例 `Chunk`。

### 5. `standard_rules`

统一保存可计算规则和证据规则。建议通过 `rule_type` 区分：

- `numeric_range`：普通上下限或区间
- `threshold`：研究/平台特异阈值
- `qualitative_direction`：升高、降低、影像学表现
- `classification`：正常、轻度、中度、重度、Stage 1–6
- `exclusion`：排除条件
- `composite`：多指标组合规则

核心字段包括：

- `version_id`、`indicator_id`、`source_segment_id`
- 比较符号、上下界和开闭区间
- 单位、性别、类别、目标状态
- `evidence_type`
- `applicability` JSONB：平台、示踪剂、年龄、队列、量表版本、设备等
- `machine_actionability`
- 优先级和冲突组标识

### 6. `standard_rule_conditions`

用于表达组合规则的条件树，例如：

- MAFLD：脂肪变性证据 + 至少一项代谢异常
- ALD：按性别区分的饮酒阈值
- AD：A/T/N 状态与认知、功能和阶段的组合

这样可以保留“不能单独确诊”“必须同时满足”等逻辑，而不是把它们压成单个范围。

## 四、`reference_ranges` 兼容投影

`reference_ranges` 暂不删除，也不再作为标准事实来源。

由已批准版本生成兼容投影，只包含当前预测链路能够安全消费的普通数值规则，并增加溯源字段：

- `standard_id`
- `standard_version_id`
- `standard_rule_id`
- 适用条件摘要或上下文哈希

投影规则要求：

1. 同一指标的不同适用条件不能互相覆盖。
2. 无法确定适用条件的研究阈值不能进入默认投影。
3. 单时点预测若仍存在，只能通过 resolver 读取投影，不能直接按 `created_at` 取“最新一条”。
4. 后续所有消费者迁移完成后，再评估是否将其改为视图或最终下线。

## 五、专用标准上传/解析链路

标准文档应与病例文档分开处理：

```text
上传并声明标准类型/疾病
        -> 保存原始文件和内容哈希
        -> 结构感知解析 DOCX 表格、章节和段落
        -> 写入 standard_segments
        -> 确定性解析数值、方向、分级和组合规则
        -> LLM 仅做候选归类/补充，不直接发布规则
        -> 冲突、缺失、单位和适用条件校验
        -> 预览差异并人工审核
        -> 发布不可变版本
        -> 生成 reference_ranges 兼容投影
```

标准内容不进入病例向量库。若未来需要检索标准依据，可针对 `standard_segments` 建立独立向量集合和独立分块策略；预测计算不依赖向量检索。

## 六、对预测报告和纵向 artifact 的影响

### 单时点预测报告

单时点预测当前直接消费 `ReferenceRange`，因此未来重构时需要：

- 改为通过标准 resolver 获取适用规则；
- 在报告中保存标准版本、规则 ID 和实际使用范围快照；
- 历史报告保留原有 `sources`、`prediction_result` 和正文，不因标准更新而静默重算。

本留痕不决定单时点预测是否保留。项目当前计划是先将该功能整体移除，之后再以本方案为基础设计标准层。

### 纵向进展/结局模型 artifact

当前纵向 artifact 的特征只来自访视序列的数值派生统计，不读取 `reference_ranges`。因此在“不把标准命中结果加入模型特征”的前提下：

- 不需要修改现有 `.joblib` 文件；
- 不需要修改现有模型 `meta.json` 的特征顺序；
- 不需要因为标准层重构而重新训练。

后续如果决定把“超出标准”“阶段阈值命中”等作为模型特征，则必须建立新的 artifact 版本、扩展特征契约并重新训练，不能直接复用旧 artifact。

## 七、建议实施阶段

1. **阶段 0：当前功能清理**
   - 由项目所有者先移除单时点预测报告相关代码、API、前端入口和测试。
   - 本方案不在此阶段实施数据库重构。

2. **阶段 1：标准层建模**
   - 新增标准集合、版本、指标、片段、规则和条件表。
   - 为两份现有 DOCX 建立 draft 版本。

3. **阶段 2：解析与审核**
   - 实现标准专用解析器、冲突检查、预览和人工批准。
   - 生成 approved 版本。

4. **阶段 3：兼容投影与消费者迁移**
   - 生成 `reference_ranges` 兼容投影。
   - 只有在未来重新启用或替换预测消费者时，才接入 resolver。

5. **阶段 4：历史兼容与清理**
   - 为历史报告补充或固定旧来源快照策略。
   - 评估 `reference_ranges` 是否改为视图或下线。

## 八、后续规格设计的验收重点

- 两份标准中的表格行、方向性内容、分级规则和适用条件不互相丢失。
- 同一指标的多研究阈值并存，不平均、不覆盖、不按写入时间择一。
- 严格边界 `<`、`>` 与含边界 `≤`、`≥` 保持原义。
- 无适用条件的研究阈值不会进入默认可计算投影。
- 解析失败、冲突和缺失内容可在发布前被发现和审核。
- 标准版本可回溯，历史结果不会因新版本发布而静默改变。
- 在不新增标准特征的情况下，现有纵向模型 artifact 校验和校验值保持不变。
