# AD 阶段转换预测：当前边界与后续扩展说明

> 日期：2026-08-26
>
> 文档类型：后续设计参考说明
>
> 关联路线图：P0-03 固定窗口训练数据集、P2-01 疾病阶段模型
> 当前决定：P0-03 直接完成当前数据条件下可审计、可正式使用的固定窗口数据集；完整 AD 阶段转换预测属于后续新增预测目标，留待现有路线图完成后单独设计，不视为对 P0-03 的返工

## 1. 这份文档解决什么问题

当前 AD 数据既包含每次访视的 CDR，也包含患者最终 CDR 和 `dementia_date`。从数据表面看，似乎可以立即训练以下所有阶段变化：

```text
正常 → MCI → 轻度痴呆 → 中度痴呆 → 重度痴呆
```

但“数据里有未来 CDR 数值”与“已经定义了可用于训练的未来事件”不是一回事。

本说明用于记录：

1. 当前数据和代码实际具有什么；
2. P0-03 为什么暂时只使用 `dementia_date`；
3. 当前版本不会实现什么；
4. 未来要扩展完整 AD 阶段转换预测时，需要先确认哪些规则；
5. 后续如何在不破坏当前训练集和模型契约的前提下增加新能力。

## 2. 通俗说明

训练模型需要两部分：

- **输入信息**：站在某一天，患者当天及以前的检查结果；
- **标准答案**：这一天之后，患者在规定时间内是否真的发生了目标事件。

例如：

```text
2024-01-01：CDR 0
2024-07-01：CDR 0.5
2025-01-01：CDR 1
```

当前数据明确提供：

```text
dementia_date = 2025-01-01
```

因此，“2025-01-01 进入痴呆”是当前已经定义和保存的事件。

当前数据没有明确提供：

```text
mci_date = 2024-07-01
mild_dementia_date = 2025-01-01
moderate_dementia_date = ...
severe_dementia_date = ...
```

程序虽然可以看到未来某次访视的 CDR 为 0.5、1、2 或 3，但如果直接把这些数值自动转换成阶段事件，就等于程序自行制定医学和业务规则。当前项目尚未正式确认这些规则。

## 3. 当前 AD 数据的真实状态

当前参考数据集为 `ad_longitudinal_300`：

- 300 名参考患者；
- 1365 次访视；
- 每名患者 3–6 次访视；
- 每次访视可以包含 CDR、MMSE、MoCA 和生化指标；
- `final_stage` 使用 CDR 分级值：`0`、`0.5`、`1`、`2`、`3`；
- `dementia_date` 表示首次出现 CDR ≥ 1 的访视日期；
- 当前没有 `mci_date`；
- 当前没有 CDR 1→2、2→3 等严重程度转换日期；
- 当前没有经过批准的其他“等价进展事件字段”。

当前疾病 adapter 保存的业务阶段顺序仍是：

```text
normal → mci → dementia
```

这表示项目知道 AD 存在正常、MCI 和痴呆阶段，不表示当前数据库已经为每个阶段转换提供了可审计事件日期。

## 4. P0-03 当前采用的正式范围

P0-03 采用当前项目数据能够可靠支持的正式固定窗口标签：

> 对尚未进入痴呆的患者，根据 `as_of` 当日及以前至少 3 次访视，预测未来 365 天内是否发生 `dementia_date`。

具体边界：

- 只使用 `dementia_date` 作为 AD 的目标事件日期；
- 不自行增加“等价事件字段”；
- 不根据未来 MMSE、MoCA、生化指标推导标签；
- 不根据未来 CDR 自动生成 `mci_date` 或痴呆严重程度转换日期；
- 最终 CDR 和未来 CDR 不进入同期特征；
- 截至 `as_of` 已真实观测到的历史 CDR 可以作为历史信息，但必须经过明确的特征禁止和时间截断检查；
- 已经在 `as_of` 当日进入痴呆的样本，不再用于训练“未来是否进入痴呆”的模型，只保留在审计统计中；
- 训练标签仍为阳性、阴性或观察不足，观察不足不由大模型补写标签。

当前范围不表示 AD 只有两个医学阶段，也不是先做一个临时小版本。它表示当前 P0-03 直接建设可供 P0-04 使用的正式数据集，而 AD 目前唯一具有明确、可审计事件日期的预测目标是“进入痴呆”。未来增加正常到 MCI、CDR 1 到 2 等目标时，应新增独立的数据集与标签版本，不推翻本数据集。

## 5. 当前版本明确不做什么

P0-03 不训练或定义以下目标：

- 正常 → MCI；
- MCI → 痴呆，若该目标需要独立于现有 `dementia_date` 的 MCI 起点确认规则；
- CDR 1 → CDR 2；
- CDR 2 → CDR 3；
- 痴呆后的功能恶化、照护需求或其他临床结局；
- 使用大模型生成阶段事件日期或训练标签；
- 使用一次未来 CDR 变化直接替代人工确认的事件规则。

这些内容不是被永久否定，而是推迟到当前路线图的基础设计和开发修改完成后再单独设计。

## 6. 为什么现在不直接用未来 CDR 当标签

未来 CDR 可以成为标签来源，但必须先有经过确认的转换规则。当前尚未回答以下问题：

1. 单次 CDR=0.5 是否足以定义进入 MCI？
2. 是否需要连续两次 CDR=0.5，或结合功能下降与临床诊断？
3. CDR 从 0.5 回到 0 时，首次 0.5 是否仍算事件？
4. CDR 1→2 是新的疾病事件，还是已有痴呆的严重程度变化？
5. CDR 1→2 或 2→3 是否需要连续确认？
6. 同日存在多次或互相冲突的 CDR 时如何处理？
7. CDR 缺失，但 MMSE/MoCA 明显下降时是否允许推导阶段？
8. 不同来源、量表版本或评估条件是否可以直接比较？
9. 当前 CDR 能否作为预测下一阶段的特征，哪些情况下会形成标签的近似复制？

如果这些问题没有统一规则，程序自动生成的“标准答案”可能只是数据生成方式或量表波动的复制，而不是真实、稳定的未来结局。

## 7. 后续建议建设的能力

完成当前路线图后，如项目所有者决定扩展 AD 阶段转换预测，建议新建独立设计任务，不直接修改现有 `dementia_date` 标签含义。

### 7.1 先定义阶段转换事件契约

建议明确区分：

```text
normal_to_mci
mci_to_dementia
dementia_cdr_1_to_2
dementia_cdr_2_to_3
```

每种事件分别定义：

- 起始阶段；
- 目标阶段；
- 允许使用的确认字段；
- 单次确认还是连续确认；
- 回退或波动如何处理；
- 事件日期如何确定；
- 缺失或冲突时是否为未知；
- 哪些字段禁止作为同期特征。

### 7.2 建立独立、可审计的派生事件层

如果最终批准使用 CDR 派生事件，建议建立单独的版本化派生逻辑，例如：

```text
ad_stage_transition_labels.v1
```

每条派生事件至少保留：

- 患者 group ID；
- 事件类型；
- 事件日期；
- 使用的访视和 CDR 证据；
- 确认规则版本；
- 是否需要人工复核；
- 冲突、缺失和回退说明；
- 真实来源或合成来源。

不要把派生事件静默写回原始访视或伪装成原始临床事实。

### 7.3 为不同预测问题建立不同模型

不建议用一个标签混合预测所有阶段。后续可以评估：

- 分阶段二分类模型；
- 多状态转换模型；
- 生存或竞争风险模型；
- 有序阶段模型。

具体采用哪种方案，需要根据真实可用样本数、事件数、观察期和模型使用场景重新设计。当前不预先选定。

### 7.4 保持与当前 P0-03 的兼容

未来扩展时应：

- 保留当前 `dementia_date` 固定窗口数据集版本；
- 不改变已发布数据集版本的标签含义；
- 新增独立 dataset/label schema version；
- 分别记录不同目标和窗口的训练统计；
- registry 必须按目标、阶段、窗口和特征版本拒绝错误模型；
- 报告明确说明模型预测的是“进入痴呆”还是“痴呆严重程度继续进展”。

## 8. 后续启动条件

建议在以下条件满足后再启动完整 AD 阶段转换设计：

1. P0-03 固定窗口训练数据集完成；
2. P0-04 至 P0-07 的基础结局模型、registry 和报告链路稳定；
3. 已明确当前模型和报告的真实使用方式；
4. 项目所有者确认需要预测哪些 AD 阶段转换；
5. 明确未来 CDR 是否可以作为派生标签来源；
6. 对每种转换完成医学和业务规则确认；
7. 重新执行只读样本和事件数量审计；
8. 另行批准设计文档和 TDD 实施计划。

## 9. 当前决策摘要

当前继续执行 P0-03，采用以下已确认决定：

- AD 业务阶段仍为 `normal → mci → dementia`；
- 当前固定窗口目标只使用明确的 `dementia_date`；
- 不自行发明 `mci_date` 或其他等价事件字段；
- 不用未来 CDR、MMSE、MoCA 或生化指标代替标签；
- 未来 365 天风险分数由 P0-04 模型产生，不由 P0-03 或大模型补标签；
- 每个纵向训练样本至少包含 3 次截至 `as_of` 的有效访视；
- 从第 3 次访视开始生成候选前缀；
- 完整 AD 阶段转换预测留待当前路线图设计开发修改完成后，依据本说明另行启动。
