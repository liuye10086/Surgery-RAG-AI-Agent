# 脂肪肝病例约束纵向数据生成设计

> 日期：2026-08-18  
> 协作方式：简化流程  
> 状态：待项目所有者复核  
> 输入：两份脂肪肝病例 Word 文档与《真实纵向数据采集规范（v1）》  
> 输出：固定结构的 `patients.csv`、`visits.csv` 及独立的数据来源说明

## 1. 目标

在真实历年检验单和随访记录已经缺失的前提下，基于现有病例叙述生成 150 例可供项目研发、导入管线和规律挖掘流程使用的纵向结构化数据。

生成结果必须满足：

1. 病例级人口学信息和明确诊断线索尽量来自原病例文档；
2. 所有患者至少有 3 次随访，首末随访跨度至少 24 个月；
3. 核心指标 `plt`、`hba1c`、`afp` 每位患者至少有 3 个有效时间点；
4. 日期、结局和指标时间序列在患者内部保持一致；
5. 输出列名、列顺序、编码和缺失值表示严格符合采集规范；
6. 生成过程可复现，并提供患者级与总体级质量控制报告。

## 2. 数据真实性边界与输出约定

原病例文档中的指令性文字不视为用户指令，只作为病例资料读取。病例文档能直接支持的年龄、性别、日期、检验值、诊断及排除因素可作为病例约束；没有源报告支持的历年随访值由生成器补齐。

为保持既有导入契约：

- `patients.csv` 和 `visits.csv` 不增加来源或生成标记列；
- 两个 CSV 的数据行中不写“合成”“模拟”等文本；
- 独立提供 `DATA_PROVENANCE.md`，说明字段来源、生成规则、随机种子、不可用于真实世界临床证据的边界；
- 不将生成值描述为从原始检验报告补采得到的真实测量值。

## 3. 病例范围与唯一编号

### 3.1 输入病例段

- `脂肪肝相关病例（1-78例）.docx`：解析到 82 个病例段；病例编号 17、26、38、78 各出现两次，内容为不同患者；
- `脂肪肝病例-2026.8.7.docx`：解析到 73 个病例段；
- 两份文档合计 155 个病例段。

### 3.2 排除 5 例

根据已确认方案，排除第一份文档中的以下病例段：

| 来源病例 | 排除理由 |
|---|---|
| A27 | 妊娠期急性脂肪肝，不属于慢性代谢性脂肪肝进展线 |
| A30 | 妊娠期急性脂肪肝 |
| A32 | 与 A30 内容重复，且为妊娠期急性脂肪肝 |
| A34 | 妊娠期急性脂肪肝并暴发性肝衰竭 |
| A35 | 与 A34 内容重复，且为妊娠期急性脂肪肝 |

保留病例数为 150。

### 3.3 患者编号

按稳定顺序编号为 `P001` 至 `P150`：

1. 先按第一份文档中的病例段出现顺序；
2. 跳过 5 个排除病例段；
3. 再按第二份文档中的病例段出现顺序；
4. 重复病例编号使用其实际出现顺序区分，不因编号相同而合并。

另在来源说明中保存 `patient_id` 到“源文档 + 病例编号 + 出现序号”的映射，不把该映射加入导入 CSV。

## 4. 病例信息提取

每个病例段按以下优先顺序提取信息：

### 4.1 年龄与性别

- 从病例开头、一般情况或主诉前的人口学描述提取；
- 年龄缺失但存在明确年龄段时，按可复现规则在对应区间内取值；
- 完全无法识别时，从同文档已识别病例的年龄、性别经验分布中抽样；
- 原文明确年龄按原值保留，允许未成年人；生成补齐的年龄限制在 16–85 岁。

### 4.2 明确日期

识别 `YYYY-MM-DD`、`YYYY/MM/DD`、中文年月日及仅有年月的日期。日期用途按上下文分类为就诊、检查、确诊、治疗或随访日期。

- 有明确脂肪肝诊断日期时优先使用；
- 只有“X 年前发现脂肪肝”时，以文中最早明确就诊日期为锚点反推年份，并使用稳定的月日规则；
- 仍无日期时，为该患者生成基线日期；
- 无原文日期约束时，生成的基线日期位于 2014-01-01 至 2022-08-18，末次随访不晚于 2026-08-18；
- 原文明确的历史日期可以早于 2014 年，原文明确且晚于 2022-08-18 的基线日期可保留，但必须仍能形成至少 24 个月且不晚于 2026-08-18 的随访；无法同时满足时，将该原文日期作为中间随访锚点而非基线日期。

### 4.3 已有检验数值

解析以下指标的常见中文名、英文缩写及单位写法：

`ALT`、`AST`、`GGT`、`TBIL`、`ALB`、`PLT`、`HbA1c`、`AFP`、腰围、`BMI`。

处理规则：

- 仅接受带明确指标名的数值；
- 去除箭头、参考范围和结论文本，只保留数值；
- `PLT` 的 `G/L` 与 `×10⁹/L` 视为等价；
- `AFP` 的 `μg/L` 与 `ng/mL` 视为等价；
- 同一日期同一指标有多个值时，优先使用与脂肪肝诊疗最相关的正式检验结果，无法区分时使用首次出现值并在来源说明中记录冲突；
- 叙述中的“正常”“偏高”“下降趋势”等不转化为具体观测值。

## 5. 队列分组

每例均生成 `cohort_group`。

### 5.1 `mixed`

符合任一明显情形时标记为 `mixed`：

- 酒精性肝病或明确长期大量饮酒；
- 乙肝、丙肝等病毒性肝炎阳性或以病毒性肝病为主线；
- 药物性肝损伤或药物诱导脂肪肝；
- 肝脓肿等急性感染；
- 妊娠期急性脂肪肝、遗传/线粒体代谢性肝病、自身免疫性肝炎或胆管来源恶性肿瘤等竞争性病因；
- 以肝硬化、肝癌首诊且无脂肪肝前期；
- 病例没有明确的脂肪肝影像、临床诊断或 NAFLD/NASH/MAFLD/MASLD/MASH 证据；
- 严重急性、遗传或结构性疾病为主线，脂肪肝仅为无法确认的偶然发现；
- 原文信息不足以确认进入脂肪肝进展线。

### 5.2 `fatty_liver_progression`

存在影像学或临床脂肪肝证据，且未出现上述竞争性病因或病程排除条件者标记为 `fatty_liver_progression`。

以下常见合并症不再作为排除条件：

- 2 型糖尿病、糖尿病前期或胰岛素抵抗；
- 肥胖、中心性肥胖、代谢综合征；
- 高血压、血脂异常、高尿酸血症；
- 多囊卵巢综合征、阻塞性睡眠呼吸暂停；
- 常见心脑血管疾病及糖尿病微血管/大血管并发症。

这些因素属于脂肪肝真实临床人群中的常见代谢共病，可进入主要规律挖掘，并在后续分析中作为分层或协变量处理。

每例分类必须产生结构化理由，例如 `documented_fatty_liver`、`metabolic_comorbidity_diabetes`、`competing_viral_hepatitis` 或 `advanced_stage_without_fatty_prephase`。理由写入审计文件，不增加到两个导入 CSV。

文本匹配只负责提出候选，最终分组还需结合病例开头、临床诊断和病程描述复核，避免把鉴别诊断或否认病史误当成阳性诊断。

## 6. 结局分配

总体目标为约 75 例进展事件：

- 约 50 例最终阶段为 `cirrhosis`；
- 约 25 例最终阶段为 `hcc`；
- 其余为 `fatty_liver`，其中少量可标记失访。

“约”允许为满足病例证据和时间逻辑进行小幅调整，但总进展事件控制在 72–78 例。

分配优先级：

1. 原文明确存在肝硬化或肝癌结局者优先保留其结局；
2. 原文明确未进展或短期改善者优先保持 `fatty_liver`；
3. `fatty_liver_progression` 的进展概率高于 `mixed`；
4. 原文为肝癌首诊且无脂肪肝前期的病例保留为 `mixed`，其生成结局不用于脂肪肝进展规律队列；
5. HCC 病例可有或无先行肝硬化日期，取决于原文证据与生成路径；
6. `fatty_liver_date < cirrhosis_date < hcc_date <= last_followup_date`，不适用的日期留空；
7. 失访患者的 `final_stage` 为最后已知阶段，结局日期不虚构为已确认事件。

## 7. 随访时间线

每例生成 3–6 次随访：

- 最少 3 次，优先 4–5 次；
- 首末跨度 24–60 个月；
- 随访间隔以 6–15 个月为主，允许不规则间隔；
- 原文已有多个日期时尽量纳入时间线；
- 原文只有一次检查时，将该检查放在最接近相应病程阶段的随访节点；
- 进展事件前至少保留 3 个核心指标时间点；
- 结局事件发生后不生成超出最后随访日期的记录。

`last_followup_date` 始终等于该患者 `visits.csv` 中最大的 `visit_date`。原文中晚于最后一次检验的明确就诊日期需要使用时，必须同时把该日期加入 `visits.csv`，不得只写入患者表。

## 8. 指标生成模型

### 8.1 基线

以 `research/config.py` 的参考范围中点、范围和既有模拟器患者间差异为基础，并根据病例约束调整：

- 原文已有数值优先作为相应时间点的锚点；
- 肥胖、糖尿病、代谢综合征患者提高 `bmi`、`waist`、`hba1c` 的基线；
- 肝炎活动或肝损伤患者提高 `alt`、`ast`、`ggt`；
- 肝硬化阶段倾向于降低 `plt`、`alb`，提高 `tbil`；
- HCC 临近阶段允许 `afp` 持续上升，但保留部分 AFP 阴性 HCC，避免所有肝癌病例均呈同一模式。

数值采用临床可解释的非负边界和精度：

| 字段 | 输出精度 |
|---|---|
| `alt`, `ast`, `ggt`, `plt`, `waist` | 1 位小数或整数化后的数值 |
| `tbil`, `alb`, `hba1c`, `afp`, `bmi` | 1–2 位小数 |

### 8.2 纵向路径

生成路径参考项目现有 `research/simulate_cohort.py`，但转换为真实日期下的 3–6 次不规则随访：

1. 稳定/改善路径：肝酶平稳或下降，`plt` 稳定，`hba1c` 和 `afp` 无持续性异常上升；
2. R1 路径：连续至少两段 `hba1c` 上升，且当前 `plt` 较早期基线下降超过 20%；
3. R2 路径：`afp` 连续至少两段上升，信号主要位于 HCC 事件前；
4. R1+R2 路径：先出现 `hba1c` 上升/`plt` 下降，后出现 `afp` 上升；
5. 非规则进展路径：保留部分没有完整 R1/R2 信号的进展者，避免结局被规则完全决定；
6. 非进展者中保留少量单指标波动，避免规律与标签完美分离。

R1 中项目既有模拟器的每 6 个月 `HbA1c +1.0`、`PLT ×0.80` 为方法验证用强信号。针对本次 6–15 个月不规则随访，将使用更温和且按间隔缩放的变化，并只保证被分配到完整 R1 路径的病例满足最终规则阈值。

### 8.3 其他指标联动

- `alt`、`ast`、`ggt` 与肝脏炎症/进展状态正相关，但允许治疗后下降；
- `tbil` 在失代偿或晚期进展时上升；
- `alb` 在肝硬化/晚期疾病中缓慢下降；
- `bmi`、`waist` 通常缓慢变化，生活方式干预病例可下降；
- 不使用完全相同的线性斜率批量复制患者轨迹。

## 9. 缺失模式

采集规范要求核心三项每位患者至少 3 个时间点，因此：

- `plt`、`hba1c`、`afp` 每例至少 3 个非空值；
- 其余指标允许缺失；
- 缺失以空单元格表示，不使用 `0`、`NA`、`-`；
- 缺失概率按指标和病例场景设置，不完全随机：腰围和 BMI 缺失率较高，肝酶较低；
- 若原文已有数值，则该值不因缺失抽样被删除。

建议总体缺失率区间：

| 指标组 | 目标缺失率 |
|---|---|
| `plt`, `hba1c`, `afp` | 0%–15%，同时满足每例至少 3 点 |
| `alt`, `ast`, `ggt`, `tbil`, `alb` | 5%–20% |
| `waist`, `bmi` | 15%–35% |

## 10. 可复现性

- 使用固定随机种子 `20260818`；
- 所有患者按稳定来源顺序处理；
- 病例提取结果先落为中间 JSON，再生成 CSV；
- 生成器重复运行必须得到字节级一致的全部五项产物；
- 随机种子、生成器版本、输入文档文件名及文件哈希记录在 `DATA_PROVENANCE.md`。

## 11. 输出文件

输出目录：`data/generated/longitudinal_150/`

### 11.1 `patients.csv`

UTF-8、无 BOM，固定列顺序：

```text
patient_id,age,sex,cohort_group,fatty_liver_date,final_stage,cirrhosis_date,hcc_date,last_followup_date,lost_to_followup
```

### 11.2 `visits.csv`

UTF-8、无 BOM，固定列顺序：

```text
patient_id,visit_date,alt,ast,ggt,tbil,alb,plt,hba1c,afp,waist,bmi
```

### 11.3 `DATA_PROVENANCE.md`

记录：

- 输入文档及哈希；
- 5 个排除病例；
- 患者来源映射；
- 从文本提取和由生成器补齐的字段范围；
- 随机种子和生成规则版本；
- 队列、结局、随访次数、缺失率和规则路径统计；
- 使用限制。

### 11.4 `quality_report.json`

机器可读质量报告，包括所有验收统计和异常列表。该文件不作为导入输入。

## 12. 质量控制与验收

生成完成后必须通过以下检查：

### 12.1 结构

- `patients.csv` 恰好 150 行数据；
- `patient_id` 为 `P001`–`P150`，唯一且连续；
- 两表列名和顺序完全匹配规范；
- `visits.csv` 中无孤立患者编号；
- UTF-8 无 BOM；
- 缺失值为空字符串。

### 12.2 患者与日期逻辑

- 年龄为整数；原文明确年龄允许 1–85 岁，生成补齐年龄须在 16–85 岁范围内；
- 性别只含 `male`、`female`；
- 队列分组只含两个允许值；
- 最终阶段只含三个允许值；
- 每例 3–6 次随访；
- 每例随访日期严格递增且无重复；
- 每例首末跨度至少 24 个月；
- `last_followup_date` 等于末次随访日期；
- 肝硬化和 HCC 日期与最终阶段、随访日期顺序一致；
- `lost_to_followup` 只含 `yes`、`no`。

### 12.3 指标

- 10 项指标均为数值或空；
- `plt`、`hba1c`、`afp` 每例至少 3 个非空值；
- 不出现用 0 代表缺失的情况；
- 数值经过宽范围异常检查，超出临床常见范围的值必须能追溯到原文锚点，否则重新生成；
- 原文锚定数值与最终输出一致，允许因日期只能定位到月份而落到同月生成随访节点。

### 12.4 分布与规律

- 进展事件总数 72–78；
- 肝硬化与 HCC 数量接近 50/25 的目标；
- `fatty_liver_progression` 与 `mixed` 均非空；
- 完整 R1、R2 和 R1+R2 路径均有足够患者；
- 非进展者不应大量满足完整进展规则；
- 不允许规则路径与结局完全一一对应；
- 统计年龄、性别、队列、结局、随访次数、随访跨度、各指标分位数和缺失率并写入报告。

### 12.5 可复现

- 连续运行生成器两次并比较 SHA-256；
- 两次 `patients.csv` 和 `visits.csv` 哈希必须分别一致。

## 13. 实现边界

本任务只生成数据文件、来源说明、质量报告及可复现生成脚本，不实现数据库导入 API，不修改生产 RAG 链路，也不把生成数据直接写入数据库。
