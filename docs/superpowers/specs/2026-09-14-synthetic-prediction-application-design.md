# 合成四任务最小应用接入设计

日期：2026-09-14。版本：0.1。状态：**设计完成，建议方案供实施前审阅；尚未实现或进行应用链路验收。**

依据：[总领文档](2026-09-09-prediction-model-refactor-master-design.md)、[阶段二第7.67节](../plans/2026-09-09-prediction-model-refactor-phase-2-task-evaluation.md)、[稳定性结果](../notes/2026-09-14-synthetic-prediction-stability-result.md)、[界面规范](../../DESIGN_SPEC.md)、[报告运维](../../OPERATOR_REPORT_OPERATIONS.md)。

## 1. 目标与取舍

在隔离测试环境中，用有明确来源的合成病例打通“鉴权 → 数值计算 → 持久任务 → 保存报告 → 历史读取 → PDF原件”。覆盖 `ad.mmse.6m`、`ad.mmse.12m`、`fatty_liver.alt.6m`、`fatty_liver.alt.12m`；每个病例只产生所属病种的两个时距。

| 方案 | 收益与代价 | 本设计建议 |
| --- | --- | --- |
| 只展示离线结果文件 | 改动少，但不能验证真实API、worker、归属、历史及归档 | 保留为离线结果入口，不作为本次全链路验收 |
| 隔离环境增加合成数值报告分支，首版仅末次值保持基线 | 可以检验四任务语义和既有基础设施；需要新增来源、报告契约和版本分派 | 推荐 |
| 同时接入Ridge／随机森林／D03对比界面 | 能交互查看候选，但增加制品选择、训练版本与展示复杂度 | 后续有明确需要再设计 |

推荐 `last_value` 是工程范围选择，不是临床算法批准。上一轮最大规模下，主分支候选在每个任务和评价池上的三种子平均MAE均未优于保持当前值；D03没有稳定的跨种子正增益。扩量解决了部分小样本波动，却没有证明生成机制中的历史信息有可泛化收益。继续机械扩大同一生成器不作为应用接入前置条件，也不能回答真实临床样本量是否充分。

本轮仅交付设计及索引更新。后续实施首包仅处理纯输入／结果契约和基线适配；数据库、界面及worker分包实施。正式临床A2–A5、容差、16个C03门槛及模型发布结论保持原状态。

## 3. 来源、输入和隔离边界

### 3.1 合成病例的服务端绑定

建议增加操作者病例的可空JSONB工程来源字段（工作名 `engineering_source`），通过Alembic迁移定义；空值代表“无工程来源证明”，不自动认定为真实数据。字段持久化严格版本对象：`source_kind=synthetic`、`is_synthetic=true`、生成器版本、来源run ID、来源manifest及输入文件SHA256、主体键、每任务输入包、输入包SHA256、绑定的病例展示投影SHA256。

首次仅由隔离验收种子程序从固定且校验通过的合成包建立病例及绑定，使用同一数据库事务。普通创建／编辑API不得写来源字段，浏览器不得上传自称可信的manifest、路径或模型文件。所有路径仅由服务器受限目录解析，禁止客户端指定任意文件或pickle。

首版工程病例为只读输入：服务端病例／访视编辑路径拒绝修改工程绑定及其输入；归档、读取和既有删除语义保留。提交时校验来源、输入、展示投影和病例归属一致；缺失、损坏或被篡改均拒绝，不从备注、患者标签或 `CASE-` 编号猜来源。病例删改不改变已保存报告。以后若需要可编辑合成病例，另设计显式新修订与重新绑定，不静默修改原输入。

来源与报告类型必须双向约束：无工程证明不能创建合成数值报告；已绑定合成来源的病例也不能通过缺省 `{}` 请求或legacy SSE生成入口创建无合成标识的旧报告。工程开关关闭时拒绝新建，不回退旧报告类型。该检查放在所有入口共享的接单服务；既有已受理任务的幂等重放及历史读取保持原身份，不重新受理或重算。

新入口建议使用一个默认关闭的工程开关 `SYNTHETIC_REPORTS_ENABLED`；它不能替代角色、疾病、归属、来源校验，也不能单靠数据库名称判定可信。实施中的隔离启动器沿用已有本机 `_test` 数据库限制，并显式配置独立私有归档目录；只给隔离API和worker注入开关，不改共享 `.env`。原报告／PDF接单开关仍分别有效。旧数据的空来源一律不能进入新分支。

### 3.2 输入契约

复用 `schemas/synthetic_prediction_cases.py:PredictionInput` 及 `services/prediction_calculation.py:project_calculation_inputs`；应用适配层补齐严格的任务／病种／指标／时距一致性及来源绑定检查，不假设离线schema已经验证全部关联。

- 服务器选取所属病种的两个固定任务，不允许客户端改变时距或模型。
- 预测函数只接收锚点时已测量、已知且可比的输入包。`measured_on`、`known_on`、单位、方法均来自包中事实，不能把visit日期补作known时间。
- 不读取 `FollowupOutcome`、完整未来观察、生成机制、评分结果或候选预测。它们仅可由离线验收程序对照，不能进入任务快照、报告或推理参数。
- MMSE单位为“分”，ALT为 `U/L`；保留已有单位、范围、重复日期、锚点、可比性及缺失规则，不自动换算或补值。
- 输入不可用有明确原因；已知无历史和未知历史继续区分，`n_pre`／跨度只由输入计算。纯基线只使用锚点值，不宣称使用了历史信息。
- 新快照包含病例／疾病／归属所需标识、匿名展示身份、两个输入包及来源绑定；日期采用各输入的anchor，不能把未来随访最大日期当锚点。

## 4. 请求、结果与不可变身份（建议契约）

以下名字为实施建议，现有API尚不支持。

| 对象 | 建议形式与关键约束 |
| --- | --- |
| 请求 | 复用 `POST /operator/longitudinal-cases/{case_id}/report-jobs`，新增严格 `report_kind=synthetic_numeric`；缺省请求继续走旧分支，仍不允许非空 `model_options` |
| 幂等 | 沿用UUID键、用户及原scope；旧请求哈希字节规则不变。新请求哈希使用独立contract标识并包含类型；相同键换类型必须冲突，重放返回原任务 |
| 输入 | `synthetic_numeric_input.v1`，固定来源与输入包，不携带未来结果；保持快照SHA256、canonicalization版本及batch绑定 |
| 结果 | `synthetic_numeric_prediction.v1`，病种、来源、anchor、算法身份及恰好两个唯一任务；每任务带indicator、unit、horizon_months、target_date、status、value、reason |
| 单任务状态 | `available` 必须有限value且reason为空；`unavailable` 必须value为空并有具体reason。结构损坏、身份冲突、非有限计算为任务失败，不伪装成正常缺失 |
| 日期 | `target_date=add_calendar_months(anchor_date, 6或12)`；不使用180／365日替代月，也不改旧365天身份 |
| 算法身份 | `last_value` + 固定算法版本、适配实现摘要、参数摘要、输入契约版本；属于无拟合基线，不冒充训练release set或临床模型 |
| 上下文 | `synthetic_numeric_generation_context.v1`，固定source/input/config/algorithm/template摘要；记录 `clinical_validity_claim=false`、`production_enabled=false` |
| 文档 | 在 `schemas/report_document.py` 增加独立严格数值文档类型 `synthetic_numeric_report_document.v1` 及解析联合；保留现有ReportDocument v1字段与校验 |
| 发布与历史 | 新建数值Publication类型与验证分支，沿用原子保存机制；独立fingerprint版本绑定snapshot、context、prediction、正文、证据说明、文档，不改旧v1／v2摘要算法 |

有有效锚点时，6月与12月基线值均等于锚点值。这表示“末次值保持的比较基线”，不表示预计病情一定不变。没有估计区间则不显示区间；不产出患病概率、风险档位、恶化方向、正常／异常预测结论或治疗建议。

算法身份必须可重现：接单时固定实现摘要，worker启动及执行校验一致；部署了不同实现时旧排队任务明确失败，不能用同名新代码重算旧任务。历史读取只验证保存内容与摘要，不依赖当前算法代码存在。

## 5. 持久任务、证据与归档

复用现有队列、用户／病例并发限制、幂等、取消、租约、心跳、deadline、父子进程及单次原子发布。接单前后均检查病例和来源修订，旧分支的活动模型／标准复核原样保留；新分支检查自己固定的算法和来源身份。worker及发布方再次核对snapshot/context/result/document/batch/disease/task/date/unit/source，不能只比较外层哈希。

接单的角色和病例归属沿用 `require_ai_operator` 与case service；疾病启用和任务适用性显式校验，不能复用旧事件任务的终末阶段限制判断新MMSE任务。按类型增加readiness，旧readiness规则不放宽。源病例必须通过普通编辑入口的内容校验；工程种子导入同样调用适用校验，不借测试数据绕过既有医疗内容过滤和审计。

新分支不调用LLM、不查临床参考病例，也不执行旧标准解释器；用类型化证据说明明确记录“合成工程报告，未执行临床标准／参考病例评价”。这是独立工程产品语义，不是把旧标准门槛改成可选。原 `standard_evidence` 阶段可记录显式 `not_requested` 工程审计事件，不能发送 `available` 或将证据完整性称为临床证据完备。新字段须检查DB状态约束与读模型映射；若需要新状态，随隔离迁移明确加入，不向旧枚举填空串。

历史列表、详情和失败／取消输入审计均需识别新类型。未知版本、篡改文档或上下文继续拒绝；既有历史及旧摘要验证不退化为宽松字典读取。源病例删除、来源文件移走或算法更新后，已保存的完整历史应仍可读取，不临时加载当前版本补齐。

PDF继续“准备任务 → worker渲染 → 原子发布 → 下载原件”，复用取消／重试限制和损坏恢复规则。新增模板身份（建议 `synthetic_numeric_report.zh-CN.v1`），更新匹配的renderer manifest与源文件摘要；不改写旧已发布PDF。下载前归属、发布状态、hash／字节／页数检查保持；没有归档时不即时渲染替代。

实施前必须检查 `AIReport` 的analysis_type／fingerprint／证据状态、任务表context、幂等scope以及PDF模板状态约束，形成实际迁移清单；本设计没有假定现有JSONB能免除全部迁移。执行迁移与编写迁移分开，后续仅在明确隔离DB验收，不迁移已有业务库。

## 6. 页面与报告展示

保持AI操作者页面职责，沿用 `docs/DESIGN_SPEC.md` 暖杏蓝、CSS变量、字号、间距、按钮与无障碍规范。合成入口只在服务端返回已验证的工程病例能力时出现，医生／患者聊天页面不增加入口。病例来源区域显示“合成工程病例”，预测动作标为“生成合成数值报告”；来源输入首版只读，解释原因。

页面／历史／PDF均显示“合成数据 · 末次值保持基线 · 尚无临床有效性结论”。主体内容依次为匿名病例与输入锚点、历史实测、6／12月结果表、输入缺失／拒绝原因、算法与来源摘要。每行同时显示目标日期、单位和可用状态；两时距相同值不隐藏。先采用表格，复用历史观察图；预测点不画成实测或连成连续疗效曲线。无需新增交互图表库。

结果表不展示训练分数作为患者级置信度，不将合成随访真值混进报告；技术哈希放到现有审计详情，主流程用普通中文解释。

复用API封装、Pinia生成任务观察、历史和归档组件；从后端schema通过 `scripts/generate_report_document_types.py` 生成联合类型，不手改生成文件。同步检查 `frontend/src/api/operator.ts`、生成任务请求、历史详情、审计、图表和错误映射。新版本不得掉入旧风险报告渲染或legacy降级显示。

界面验收覆盖：来源未验证／功能关闭、加载、空历史、输入不可用、接单失败、排队、运行、取消、过期登录、重连、完成、历史损坏、PDF排队／失败／已发布；刷新只恢复观察，不能自动创建新任务。
