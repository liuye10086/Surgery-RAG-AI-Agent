# 安全加固与版本化索引设计

## 目标

在不改变产品主要使用体验的前提下，修复以下四个已确认的问题：

1. 防止已登录用户读取自己没有引用权限的完整病例文档。
2. 确保被安全规则拒绝的问题不会写入数据库，也不会在后续对话中重新进入模型历史。
3. 在保留逐句流式体验的同时，阻止包含确定性诊断或具体药物剂量的危险句子发送给用户。
4. 重新解析、分块和向量化失败时，继续保留当前可用的知识库版本，避免旧知识突然下线。

## 改动范围

本次改动包含：后端权限校验、聊天消息持久化、输出安全过滤、文档解析与分块、向量索引、数据库结构、前端聊天请求和回归测试。

本次不包含：完整医疗数据脱敏系统、后台任务队列、新的管理员操作页面，以及与这四个问题无关的架构重构。

## 一、统一文档访问权限

### 权限规则

管理员可以查看全部文档和图片。

普通用户只有在自己的某条 AI 回答中实际引用过目标文档时，才能查看该文档的完整内容。判断依据是：该用户会话中的 `assistant` 消息，其 `sources` 中存在与目标一致的 `document_id`。

病例图片除了要求文档已被引用，还要求目标图片 URL 确实出现在该引用来源的 `images` 中。

### 代码结构

把基于引用来源的权限判断抽取到独立的权限辅助模块，由“查看完整病例”接口和“查看病例图片”接口共同调用。

权限查询必须把消息表与会话表关联，并限定 `sessions.user_id` 为当前登录用户，防止其他用户的引用记录产生授权。

完整病例接口行为：

- 文档不存在时返回 `404`。
- 文档存在但当前用户没有引用权限时返回 `403`。
- 有权限时只返回当前生效代次的分块。

### 兼容性

已有回答中的 `sources.document_id` 继续有效，不要求重新生成历史回答。

现有第一代图片 URL 在迁移期间继续兼容，避免历史引用中的图片立即失效。

## 二、安全且幂等的用户消息持久化

### 新的请求流程

前端发送问题时，不再先调用 `/messages` 保存用户消息，而是直接调用 `/ask`。

后端严格按照以下顺序执行：

1. 验证用户身份和会话归属。
2. 校验输入长度并执行越狱、提示词注入过滤。
3. 处理前端提供的幂等请求标识。
4. 只有输入通过安全检查后，才保存用户消息。
5. 执行 RAG 检索和回答生成，并保存 AI 回答。

被安全规则拦截的输入返回 `422`，同时满足：

- 不创建用户消息。
- 不创建审计日志。
- 不更新会话标题。
- 不会在以后加载为 LangChain 对话历史。

### 幂等处理

`AskRequest` 增加 `client_request_id`。前端每次正式发送问题时生成一次该标识。

`messages` 表增加可为空的 `client_request_id` 字段，并建立 `(session_id, client_request_id)` 条件唯一索引。相同请求因网络重试再次到达时，后端复用已有用户消息，不重复插入。

现有 `/messages` 接口暂时保留以兼容旧调用，但它也必须在保存前执行相同的输入安全检查。当前前端主流程不再使用该接口。

### 重试回答

AI 回答重试继续使用 `retry_message_id` 更新原有 AI 消息。

回答重试不创建新的用户消息，因为原问题已经存在。前端发起回答重试时不提供新的 `client_request_id`。

## 三、逐句输出安全过滤

### 流式输出方式

后端不再把大模型返回的原始 token 直接发送给前端，而是先放入句子缓冲区。

遇到以下边界时形成一个待检查句子：

- 中文句号、问号、感叹号和分号。
- 英文句号、问号、感叹号和分号。
- 换行符。

每个完整句子在发送 SSE 事件之前调用输出过滤器：

- 安全句子原样发送。
- 命中确定性诊断或具体药物剂量规则的句子不发送原文，替换为统一安全提示。

统一安全提示为：

> 该部分内容涉及需要由执业医生结合实际情况判断的诊断或用药信息，已为您隐藏。请咨询主管医生。

大模型输出结束时，缓冲区里没有结束标点的剩余文本也必须执行相同检查，检查通过后才能发送。

### 保存与审计

系统只累计过滤后的文本作为最终回答。

以下位置保存的内容必须完全一致：

- 前端通过 SSE 收到的回答。
- 数据库中的 AI 消息 `content`。
- LangChain 消息 `lc_message`。
- 审计日志中的 `response_text`。

如果发生替换，`safety_flags` 记录输出被替换，并记录命中的规则类型。

引用解析基于过滤后的最终回答。被危险句子一起删除的引用标记不会形成来源授权，因此不会让用户获得对应文档或图片的访问权限。

### 异常处理

如果大模型在句子尚未检查前发生异常，不能因为异常而把缓冲区里的原始危险文本发送给用户。系统进入现有错误处理流程。

## 四、版本化文档处理与向量索引

### 数据结构

数据库增加：

- `documents.active_generation INTEGER NOT NULL DEFAULT 1`：文档当前生效代次。
- `chunks.generation INTEGER NOT NULL DEFAULT 1`：分块所属代次。

在 `(document_id, generation)` 上建立索引。

保留 `chunks.is_current`，用于快速筛选和兼容现有代码。系统要求当前代次的分块为 `is_current = true`，其他代次为 `false`。

迁移时，现有文档和分块统一设为第 1 代，现有有效分块继续保持有效。

### 图片目录

新解析出的图片按照代次保存：

```text
uploads/images/{document_id}/{generation}/{filename}
```

新的受保护图片 URL 必须包含代次。

图片接口同时提供：

- 包含代次的新路由。
- 兼容已有第一代引用的旧路由。

### 向量标识

PGVector 中的向量 ID 必须在不同代次之间保持唯一，不能只使用业务分块 ID。

使用确定性标识：

```text
document-{document_id}-generation-{generation}-chunk-{chunk_id}
```

向量元数据中保存：

- `chunk_id`
- `document_id`
- `generation`

检索时，根据元数据中的 `chunk_id` 关联业务分块，并额外要求：

- `chunks.is_current = true`
- `chunks.generation = documents.active_generation`

这样即使旧向量尚未清理，也不会被返回给用户。

### 新版本构建与切换

管理员重新处理文档时，使用：

```text
next_generation = active_generation + 1
```

处理流程：

1. 解析原始文件，不修改当前在线资源。
2. 把新图片保存到下一代目录。
3. 创建下一代分块，并设置 `is_current = false`。
4. 为全部下一代分块创建向量。
5. 验证每个新分块均成功写入向量。
6. 在同一个数据库事务中完成切换：旧分块设为非当前，新分块设为当前，更新 `documents.active_generation` 和文档状态。
7. 切换成功后，再清理旧代次的向量、分块和图片目录。

在第 1 至第 5 步期间，用户检索继续使用原来的当前代次。

### 失败处理

在正式切换前发生任何失败时：

- 只删除未完成的新代次分块、向量和图片目录。
- 原有当前代次继续提供检索和完整病例查看。
- 文档记录失败原因。
- 管理员可以重新尝试。

完成切换后，旧资源清理采用尽力而为策略。清理失败可以暂时留下不再使用的旧资源，但不能回滚或破坏已经生效的新代次。

### 管理操作

- 初次上传继续创建 `pending` 文档，并预留第 1 代。
- 文档分块和向量化的底层实现使用统一的安全代次构建服务。
- 如果管理端继续保留“分块”和“向量化”两个按钮，两个阶段必须保存明确的待发布代次状态，不能提前删除当前代次。
- 删除整个文档时，删除该文档所有代次的向量和图片目录。
- 删除单个当前分块时，删除对应代次的向量，并同步维护文档状态。

## 五、数据库迁移

在 `007_add_safety_flags.sql` 之后新增一个编号迁移脚本，执行：

1. 给 `documents` 增加非空的 `active_generation`，默认值为 1。
2. 给 `chunks` 增加非空的 `generation`，默认值为 1。
3. 给 `messages` 增加可为空的 `client_request_id`。
4. 建立 `(session_id, client_request_id)` 条件唯一索引，只约束 `client_request_id IS NOT NULL` 的记录。
5. 建立 `(document_id, generation)` 索引。

同步更新 `database/schema.sql` 和 SQLAlchemy 数据模型。

## 六、测试方案

### 权限测试

- 管理员可以查看任意完整文档。
- 普通用户可以查看自己 AI 回答引用过的文档。
- 普通用户不能查看自己未引用的文档。
- 其他用户的引用不能给当前用户授权。
- 新旧两种图片 URL 都必须执行相同的用户归属校验。

### 聊天安全测试

- 被拦截的输入不会创建用户消息。
- 相同 `client_request_id` 重复请求只创建一条用户消息。
- 被拦截的问题不会进入之后的对话历史。
- 安全句子原样流式输出。
- 包含确定性诊断或剂量的句子在发送前被替换。
- 数据库 AI 消息、审计日志和 SSE 内容保持一致。

### 版本化索引测试

- 下一代向量写入失败时，上一代仍然是当前版本。
- 新版本构建成功时，当前标记和 `active_generation` 一起切换。
- 检索忽略非当前或尚未完成的代次。
- 清理操作只删除已废弃代次。
- 现有第一代数据仍能正常检索和访问。

### 完整验证

实现完成后执行：

- 全部后端单元测试。
- 前端 TypeScript 类型检查。
- 前端生产构建。
- 如果当前数据库和 BGE-M3 模型可用，重新执行 10 条 RAG 基线评测。

## 七、运行与交付说明

生产环境不应继续使用默认的 `JWT_SECRET=change-me-in-production`，但该项生产加固不属于本次四个问题的修复范围，除非它影响新测试运行。

当前项目的 `.git` 目录没有有效 Git 元数据，因此无法创建正常的阶段性提交。除非之后单独初始化 Git，否则本次代码修改将以未提交文件形式交付。
