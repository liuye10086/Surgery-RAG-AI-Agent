# P0-07 双疾病完整纵向报告模板设计

> 日期：2026-08-27
> 路线图任务：P0-07——重构完整报告模板并完成双疾病端到端验收
> 状态：设计稿，待项目所有者批准后实施

## 1. 设计目标

为脂肪肝和阿尔茨海默病（AD）生成一份真正完整、可阅读、可追溯的纵向报告。网页、数据库中保存的 `content`、历史报告和 PDF 均使用同一份持久化报告正文；历史报告重新打开时只读取已保存内容，不重新计算，也不受病例后续修改影响。

报告只消费 P0-06 已生成的结构化 `progression_signals`，模板层不重新计算疾病规则、观察次数、单位判断或模型贡献。

## 2. 已确认的产品选择

### 2.1 报告入口

采用独立报告阅读页。进入报告后暂时隐藏病例编辑区，提供“返回病例”和“下载 PDF”。这样可清楚区分“正在编辑的病例”和“已经保存的报告”。

### 2.2 页面阅读方式

11 个部分默认连续展开，并提供快速目录。重要的模型可用状态、数据限制和人工复核重点不藏在折叠区；目录用于跳转，不改变正文内容。

### 2.3 图表范围

采用安全版图表规则：

- 有至少 3 次有效观察、单位一致且可比较的指标，绘制“已观察到的变化”趋势图；
- 只有 1～2 次有效观察的指标仍进入完整表格，但不连成趋势线，并说明数据不足；
- 单位冲突、单位缺失或单位不受当前标准支持时，保留原始观察和问题说明，不伪造趋势或异常判断；
- 不为了凑数强行生成三条信号；
- 图表标题和说明明确写“已观察到的变化”，不把观察事实写成预测。

未来若把指标改成“指标决定单位”的下拉选择，前端会减少录入错误；后端和 P0-06 的单位保护仍保留，用于历史数据、接口数据和异常输入。

### 2.4 摘要样式

摘要顶部使用三个紧凑状态块，依次回答：

1. 数据够不够；
2. 模型是否可用；
3. 实际看到了哪些信号。

状态块下面增加一小段普通中文解释，说明模型缺失会影响哪个结论、哪些内容仍然可靠。摘要不使用“未估计”作为无解释占位词。

### 2.5 PDF 样式

PDF 保留与网页相同的图表、表格和章节顺序。摘要、关键表格、关键进展信号和人工复核重点尽量作为不可拆分块排版，避免跨页断开。PDF 的所有正文来自数据库 `report.content`，不单独重新生成另一份文本。

## 3. 报告正文结构

### 1. 报告摘要

顶部状态块显示数据、模型、信号三项状态；下方用普通中文解释可靠范围和当前限制。

示例（模型未启用时）：

> 数据够用：已有 3 次有效观察。365 天风险模型暂不可用，因此不能给出未来风险分数；这不影响对过去观察变化的描述。当前形成 2 个关键进展信号，需人工复核，不构成诊断或治疗建议。

### 2. 病例与预测范围

显示疾病名称、匿名病例标签、访视次数、首末访视日期、观察跨度、当前报告生成时间和本次预测范围。患者身份信息不进入验收证据。

### 3. 数据质量与适用性

使用结构化观察摘要展示：有效观察数、缺失情况、单位状态、时间跨度、是否达到三次信号最低要求。对每个受影响指标说明“数据不足”“单位不一致”“单位缺失”或“标准不适用”。

### 4. 已观察到的纵向变化

这是事实章节，只使用实际访视数据。对符合图表规则的指标提供趋势图；全部指标进入表格，表格列出首次值、最近值、变化、有效观察次数、单位和展示限制。不得把斜率或方向写成未来预测。

### 5. 未来 365 天进展风险

仅在 outcome 模型状态为可用时显示模型风险等级、模型分数语义和校准状态；分数明确不是临床概率。模型不可用时必须说明缺少什么、因此影响“未来 365 天风险分数”这一结论，不猜测风险等级。

### 6. 阶段模型和下一次随访趋势的可用状态

分别展示 stage 和 trend 的可用性。不可用时写明“尚未配置/未启用，因此未预测下一阶段或下一次随访数值”，不能只显示“未估计”。CDR 只能在观察章节或信号章节中作为阶段相关观察，不写成阶段模型结论。

### 7. 关键进展信号

只渲染 P0-06 返回的 `signals`，不在模板层重新判断。每条信号分开显示：

- 观察事实：首次值、最近值、变化方向、有效观察次数和时间跨度；
- 标准解释：正式参考范围、标准版本/规则来源、适用性和单位限制；
- 模型关系：是否命中本次 outcome 的真实 feature contract；
- 个体贡献：固定显示“暂无可靠的个体模型贡献信息”，`model_contribution` 继续为 `null`；
- 人工复核提示：由结构化限制转成普通中文。

不得显示 `progression_signal`、`likely_rising`、`direction_only` 等内部英文状态。

### 8. 参考标准和相似病例

标准来源显示标准版本、规则来源、单位和适用性；evidence-only 标准只作为证据说明，不能伪造数值参考范围。相似病例只显示匿名、脱敏后的来源描述和相似指标，不把相似病例当作本病例结论。

### 9. 不确定性与局限性

集中列出缺失数据、单位问题、标准缺失、模型未启用、模型未校准、观察次数限制和历史 v1 兼容说明。每条限制说明它影响哪个结论。

### 10. 人工复核重点

只生成结构化复核事项，不提供诊断或治疗建议。示例：核对三次 ALT 的采样条件和单位；确认认知评分量表版本；复核标准适用人群；确认模型缺失对风险结论的影响。

### 11. 模型和数据技术附录

面向审计和医生复核，使用中文说明数据快照、观察时间范围、模型任务、模型版本、状态、特征契约摘要、标准版本和报告生成时间。不得泄露数据库 URL、密码、本机路径、traceback 或患者身份。

## 4. 数据与持久化边界

报告生成时保存以下内容：

- `input_snapshot`：病例和访视的确定性输入快照；
- `prediction_result`：P0-06 结构化预测和信号结果；
- `sources`：标准和相似病例来源；
- `content`：最终中文报告正文。

网页当前报告、历史报告和 PDF 均读取 `content`。历史查看不得调用预测服务；病例修改不得更新旧报告的 `content`。生成中断或失败时保存安全状态和错误码，不向用户展示 traceback。

## 5. 前端设计边界

- 严格遵循 `docs/DESIGN_SPEC.md` 的暖杏蓝色彩、间距、圆角、阴影、排版和医生工作流规范；
- 报告独立阅读页使用现有组件和图标库；
- 页面信息紧凑可扫描，支持桌面和移动端；
- 不在病例编辑器下方重复嵌入同一份报告；
- 打开历史报告时清理实时预测状态，避免显示上一份病例的残留结果；
- 历史报告的参考来源组件兼容标准来源和相似病例来源，不能显示“未知来源”代替已有来源信息。

## 6. PDF 设计边界

- 使用现有 PDF 工具和 PDF skill；
- HTML 模板直接渲染持久化 `content` 对应的章节与结构化表格/图表；
- 对摘要、关键表格、关键进展信号和人工复核重点使用不可拆分布局；
- 逐页渲染成图片检查中文字体、分页、表格、页脚、空白和移动/打印可读性；
- 脂肪肝和 AD 各生成匿名验收样例，证据中不出现患者身份和本机路径。

## 7. 验收场景

必须覆盖：

1. 脂肪肝三次访视完整报告；
2. AD 三次访视完整报告；
3. outcome 可用、stage 不可用的部分可用报告；
4. 标准缺失和单位问题的降级报告；
5. 模型异常、生成中断、保存、历史查看和 PDF 下载权限；
6. 历史报告在病例修改后保持不变；
7. 页面、数据库 `content`、历史记录和 PDF 正文一致；
8. P0-06 结构化信号、存量纵向报告接口和旧 progression API 回归；
9. 前端类型检查、构建和相关 Node 合约；
10. 桌面与移动端页面无溢出、遮挡或错位；
11. PDF 逐页视觉检查通过；
12. `git diff --check`、保护目录范围检查和全量 pytest。若 `.superpowers/sdd` 仍导致失败，必须如实记录，不声称全量通过。

## 8. 不在本任务范围内

- 不修改或训练 `backend/app/ml_models` 下生产模型；
- 不修改数据库 schema 或 Alembic migration；
- 不修改旧 progression engine 和旧 `/progression-predictions` API；
- 不正式启用新的 outcome/stage/trend 生产模型；
- 不调用 LLM 生成报告事实、信号或临床结论；
- 不把模板层变成新的业务规则计算器。

## 9. 设计批准后的实施顺序

设计批准后，另行编写详细实施计划，并严格按 TDD 执行：先新增会失败的契约测试，再编写最小实现；完成后运行后端、前端、Node、PDF 视觉和全量回归验收。实施期间不自动 commit 或 push。
