# 脂肪肝与 AD 预测模型重构总领文档

日期：2026-09-09。版本：0.6。状态：**阶段一当前范围的两病种 Excel 清洗交付已完成，包含用户年龄／性别补充及来源定位列删除；患者独立性、真实访视及临床终点未代签为已核准。**

目标：在现有 AI 操作者纵向报告系统上，建立面向真实病例、可以验证泛化能力的预测模型。保留已经建设的报告、版本、任务与归档基础设施，优先重建真实观测数据、预测任务和评估方法，再按证据选择算法。

## 2. 现状与证据边界

本节依据 2026-09-09 本次会话的代码与文件审查；代码基线为 `29c0997`。后续实施前应检查变更，不能将本节自动当成届时仍成立的环境事实。

### 2.1 已核查的当前实现

当前主路径是：保存病例与访视 → 受理时固定输入和生成上下文 → worker 加载固定模型套件 → 构建表格特征并推理 → 读取标准与相似病例 → 规则解释 → 结构化报告 → 保存和独立 PDF 归档。

- 当前报告主路径没有让外部 LLM 计算预测分数；相似病例是预测后的证据补充，没有参与当前分数计算。
- 当前活动模型数据快照每病种含 30 个合成患者，患者划分为训练 18、验证 6、锁定测试 6；该快照的真实训练患者数为 0。
- 已保存的三个结局模型测试 AUC 为 1.0；当前阶段与趋势模型相关分类指标同样为 1.0。这些是合成演示评估记录，不是实际临床泛化结果。
- 演示生成器的同病种患者共享固定访视节奏和高度相似的轨迹、事件位置。因此，高分主要反映模板识别能力是合理推断，尚未通过专门消融实验量化。
- 特征主要为末次值、均值、变化、斜率、缺失与访视统计。结局和阶段任务采用 365 天窗口，趋势任务为不固定间隔的下一次随访方向。
- 当前趋势标签统一采用 5% 相对变化容差；当前模型未校准，风险层级来自程序中的分数分段。
- 当前信号解释区分观察、参考规则与模型输入关系，没有计算个体模型贡献。
- 当前 release set 要求病种固定任务集合完整，readiness 依赖统一的最低访视数和适用结局路由。任务独立成熟是拟议变更，不能直接通过放宽现有检查实现。

本次会话此前运行的特征、预测契约、信号解释、输入审计测试共 67 项通过。该结果只证明对应软件行为；不是本文件编写时重新运行的完整基线，也不证明模型准确率或生产环境容量。

## 3. 目标数据与预测契约

### 3.1 真实观测与结局

先形成离线、受控、可追溯的数据版本，再考虑与业务数据库衔接。优先复用已有数据集清单与哈希机制，不为首次盘点迁移或写入业务数据库。

每条观测需要能表达：匿名患者与来源组、来源文件及原文定位、指标与数值、单位、样本类型、检测方法或量表版本、观察时间及精度、当时已知治疗、缺失原因、审核结果。患者／家系／同源病例映射仅存放于获准的私有位置。

- 保留绝对日期、相对时间、仅年份、时间区间和未知时间之间的区别。能明确“距基线 14 个月”时保留相对关系，不生成任意具体日期。
- 日期不精确时，只用于任务允许的时间表达；不能据此强行生成严格 365 天标签。事件仅能定位到区间时，按任务规定使用区间删失方法或排除相关样本。
- 同一患者多次入院、重复整理、家系关系和跨文件重复在划分前处理；无法确认独立性的记录不进入锁定测试集。
- 当前阶段必须对应预测锚点，不能从最终诊断倒填。未来访视、未来治疗和未来结局不进入特征。
- 原文缺失值保持缺失。统计插补只能在获准的模型预处理内拟合，并记录策略；不回写为真实检查结果。
- 结局明确区分已发生、完整窗口未发生、观察不足、不适用和待核实，并记录确认依据与末次随访。
- 合成数据仅继续用于流程、异常和排版测试，不计入真实模型正式评估；测试集不由真实病例扩增或复制充数。

每个正式纳入的目标标签都须有复核记录。自动提取可以产生候选，但不能自行批准临床标签。需要专业判断的疾病归属、事件定义与临床变化阈值由用户指定的具备相应能力的复核者确认。

### 3.2 每个任务必须在训练前固定的内容

| 契约内容 | 必须回答的问题 |
| --- | --- |
| 使用场景与人群 | 给谁使用，基线处于什么阶段，哪些病因和共病纳入或排除 |
| 预测锚点与信息边界 | 在哪次访视预测，当时哪些信息确实可获得 |
| 目标与时间窗 | 预测什么，多久以后，允许什么随访误差和日期精度 |
| 标签与删失 | 如何确认事件、未发生、观察不足和区间事件 |
| 输入条件 | 必需指标、单位、检查平台、最低历史量和允许缺失范围 |
| 治疗语境 | 预测基于何种已知治疗状态，如何处理预测后的干预变化 |
| 输出与适用范围 | 数值、方向、分类分数或概率分别代表什么，何时不估计 |
| 评价与准入 | 主指标、基线、误差容忍、精度要求和失败条件是什么 |

训练样本数量与推理最低访视数分别定义。基线加一次未来复查可以形成基线预测的训练对，但不等于具有两次历史观测加未来标签的纵向样本。不能为了通过现有三次访视门槛补造记录。

## 4. 两病种的建模路线

### 4.1 AD

优先补齐公开队列的诊断、访视日期、认知／功能量表和人口学数据，再核对与本地病例的共同特征。ADNI 的具体下载表、字段和适用阶段以当时官方数据字典及使用条件为准；本地影像索引不能代替临床表。

阶段二在以下候选中确定一个首发主任务：

1. 痴呆前人群的固定窗口诊断转归；应区分临床痴呆与 AD 病因定义，不将所有痴呆自动视为 AD。
2. 已确诊 AD 人群在固定窗口的认知或功能变化；量表、时间窗和变化含义由可用数据与使用场景决定。

不预先承诺两个任务同时上线。若本地病例以已确诊 AD 为主，应优先评估第二类任务能否满足真实使用需求；不能仅因当前代码存在转归任务就沿用不匹配的人群。

输入设计以真实可得性为基础。脑脊液与血浆、p-Tau181 与 p-Tau217、不同量表版本不直接合并。评估由基础临床指标构成的模型；增加生物标志物或影像定量特征时，使用独立且明确的输入契约，验证覆盖率和增量收益，不通过大规模插补假装检测齐全。

公开队列用于开发与独立留出评估，本地病例用于迁移适用性验证。若本地数据参与训练或校准，应另留未参与适配的患者评估。无法形成可靠本地测试集时，只报告外部队列结果与本地适用性限制。

### 4.2 脂肪肝

先盘点真实生化、肝硬度或其他有效重复测量，确认病因、治疗条件和复查时间。短期指标变化不能被直接命名为纤维化进展或肝癌风险。

- 若重复测量支持：选择一个有明确时间窗和足够审核样本的指标变化任务，先验证其相对简单基线的收益。
- 若存在足够可靠的进展事件及无事件随访：再设计肝硬化／肝癌事件任务；随访不齐时评估生存分析，不能将观察不足当阴性。
- 若现有资料不能支持上述任务：完成真实纵向观察、标准解释与数据缺口说明，暂不接入新的统计预测。该阶段成果标为“数据整理／观察能力完成，预测未具备条件”，不能宣称预测重构完成。

FLD1 的当前 NAFLD 状态分类仅作为单独说明用途的可选方法实验；既有用户已经管理脂肪肝病例时，不为了使用该数据而改变主要产品目标。不以 FIB-4 公式复现冒充纤维化预测。

## 5. 小样本方法与评估规则

### 5.1 候选方法

优先建立可解释且可复现的简单基线，再与现有随机森林、适用的树模型比较。根据任务分别使用正则化分类／回归，事件时间任务再考虑生存模型，不要求所有任务使用同一算法。

TabPFN 等表格基础模型可作为离线对照候选。其已有研究结果仅支持开展实验，不代表在本项目中一定优于简单模型。涉及新依赖、模型权重、许可、内存或运行时不兼容时，先在阶段计划中说明；不为实验静默升级项目固定环境，不通过外部推理 API 上传病例。

迁移学习优先考虑同病种、可对齐输入和目标的公开队列。少量本地病例可用于有限参数适配或校准，但必须保留评价独立性。当前不从零建立跨脂肪肝和 AD 的元学习框架。

LLM 的少样本提示可用于辅助信息提取；如需实际调用，需另行明确数据处理方式和授权。LLM 不补造标签、检查值或随访，不替代数值预测与人工审核。

### 5.2 必需的对照与防泄漏措施

- 分类／事件任务比较基本信息、末次指标、增加历史特征三组；连续指标任务比较维持末次值、合理的历史趋势外推和候选模型。
- 增加访视次数、观察跨度等随访节奏对照，检查模板或流程信号；不能把流程特征的重要性直接解释为疾病机制。
- 同一患者的所有窗口放在同一分区；家系及同源重复按分组处理。多个窗口不作为多个独立患者报告样本量。
- 特征选择、插补、标准化、调参、阈值选择和校准均限制在开发数据内部；不得读取锁定测试结果后反复调优并继续称其为独立测试。
- 小样本内部评估采用适用的分组交叉验证或重采样；能否保留独立测试集按事件数、样本量及估计精度决定，不机械照搬 18/6/6 比例。
- 数据支持时补充跨时间或来源验证。时间划分须说明评价新患者还是既有患者后续访视，不混称两种泛化能力。
- 特征消融、比较人群和指标预先固定；不得在结果出来后只挑有利病种、窗口或亚组报告。

### 5.3 性能、不确定性与停止条件

分类任务评价判别、校准和预定阈值表现；连续任务评价误差、偏差及适用的预测区间覆盖；生存任务使用适用的时间相关指标并检查删失假设。Brier 分数不单独作为校准充分证明。

报告实际独立患者数、事件数、缺失构成和患者／家系层面的不确定性。模型适用范围内的年龄、阶段、检测条件和缺失程度应有分层检查；支持不足的亚组标为无法可靠评估。

不在本总领文档中凭空指定 AUC、误差或样本数门槛。阶段二必须在查看锁定测试结果前确定主指标、基线比较方式、容许误差及估计精度要求，形成有复核人的任务卡。没有完成这些定义，不进入正式训练评价。

不能稳定优于基线、校准或精度不合格、缺少独立评价、样本支持不足时，不进入模型发布阶段；保留失败结果和适用性结论。不能通过增加合成患者、删除困难样本或降低既定标准制造通过。

## 6. 系统衔接与兼容原则

以下为需要在阶段四详细设计的变更边界，不是现有系统已经具备的能力。

1. **任务级输入要求。** 将最低历史量、输入字段、单位和人群限制绑定具体任务；旧模型仍遵守旧契约，不统一把三次访视门槛改成一次。
2. **任务集合的版本化。** 从病种固定完整模型套件逐步转为版本明确的能力集合。声明未提供某任务，与已声明制品丢失或损坏必须分开；前者显示不可用原因，后者继续完整性失败，不允许静默降级。
3. **报告受理条件。** 受理时固定实际选择的任务和版本。仅观察报告与预测报告的名称、完成标准和缺失说明需明确；报告内容生成成功不代表所有预测成功。
4. **输出语义。** 不继续将未验证分数分段称为已验证临床风险层级。概率、分类分数、观察方向和未来预测分别表达；数值预测及区间只在模型支持且验证后输出。
5. **解释边界。** 规则信号与模型贡献分开。后续增加归因也只能解释模型行为，不能解释为因果关系。现有阶段单调限制和统一趋势容差必须按新任务重新审查，不能当作无须验证的临床事实。
6. **历史兼容。** 使用新的数据、任务、特征与报告契约版本，不重写旧快照，不重算旧报告。新版本必要的 schema、前端生成类型、调用方及兼容读取同步更新。
7. **运行授权与证据状态。** 沿用并明确当前 active 指针的运行授权语义；现有 artifact 的 `production_enabled` 不是单独运行开关。临床证据状态、校准状态和真实数据构成应真实披露，不通过翻转旧字段伪造证据升级。
8. **上线与回退。** 新模型先离线验证、隔离环境验收，再按授权切换活动版本。切换只影响新任务；回退不删除新旧制品或历史事实。仅在接受旧输出限制的范围内回退，不能将演示模型包装为真实预测备用模型。

复用的主要入口如下，具体改动文件由阶段实施计划根据届时代码确定：

| 职责 | 当前入口 |
| --- | --- |
| 数据与标签 | `longitudinal_dataset.py`、`longitudinal_dataset_export.py`、`longitudinal_group_split.py` |
| 特征与训练 | `longitudinal_features.py`、`longitudinal_model_training.py`、`longitudinal_stage_training.py`、`longitudinal_trend_training.py` |
| 评估与发布 | `longitudinal_model_evaluation.py`、`longitudinal_release_set.py`、`longitudinal_model_registry.py` |
| 适用性与推理 | `operator_case_readiness.py`、`longitudinal_task_routing.py`、`longitudinal_prediction.py` |
| 固定上下文与报告 | `report_generation_context.py`、`report_input_audit.py`、`report_document_builder.py`、`report_publication.py` |

以上服务位于 `backend/app/services/`。报告契约来源为 `backend/app/schemas/report_document.py`；worker 入口为 `backend/app/workers/report_execution.py`。

## 7. 分阶段交付与验收

各阶段先写范围明确的实施计划。任务定义、临床标签和准入标准等实质选择交用户确认；已明确范围内的常规实现和验证不反复索取许可。训练、数据下载或导入、业务库迁移、发布分别按对应阶段的明确授权执行，不将本草案视为这些操作的授权。

两个病种允许按数据条件分别通过验收，不因其中一个缺数据而伪造其完成状态，也不阻塞另一病种可独立开展的工作。

| 阶段 | 工作与交付物 | 验收及下一步条件 |
| --- | --- | --- |
| 阶段零：总领文档确认 | 审核本文件的目标、路线、约束与执行顺序 | 用户明确批准；批准前不实施模型重构 |
| 阶段一：真实数据盘点 | 受控来源清单、重复／家系映射、候选观测与结局、人工复核清单、各病种可用性报告；列明 AD 缺少的临床表 | 原文定位可追溯；独立患者与候选窗口分别计数；来源、时间精度、单位和未知结局保留；给出数据能支持与不能支持的任务。先完成现有本地文件盘点，外部数据取得条件单列 |
| 阶段二：任务与评估冻结 | 每病种首发任务卡、标签审核记录、数据字典、患者分组策略、评估指标与准入标准、受控数据版本 | 目标人群、窗口、标签、删失、输入及评价均明确；用户确认实质任务选择，必要临床定义完成专业复核。数据不够时转入补数据或观察能力，不进入正式模型训练 |
| 阶段三：离线基线与候选比较 | 基线／纵向增量实验、适用的小样本候选、独立评估、模型说明和失败分析 | 使用冻结版本且无泄漏；结果完整披露；只有满足阶段二标准的模型才进入接入设计。候选不合格不改活动指针 |
| 阶段四：契约与报告接入 | 对已具备条件的能力编写详细设计并实施；覆盖任务级输入、发布集合、输出语义、前后端及旧报告兼容 | 新行为成功／失败／权限路径验证；缺失任务与损坏制品区分；旧报告和 PDF 原件保持可读；需要的数据库与 worker 链路在隔离环境验收 |
| 阶段五：获准发布与持续评价 | 发布核对记录、模型证据说明、回退方案及后续真实结局评价安排 | 单独确认目标环境与发布范围；真实链路、容量和运维条件满足；后续结局回流不自动触发重训或模型替换 |

### 7.1 阶段一的首个实施包

阶段一已获准，仅针对已经提供的本地文件形成可复核清单：

1. 固定来源身份，检查段落、表格及内嵌图片中的数据承载情况，说明文本提取覆盖与未读部分。
2. 提取候选观测与时间关系，标注重复、家系、病因、检测情境及治疗上下文。
3. 逐例记录哪些结局已证实、哪些随访不足，以及需要回查原始记录的具体问题。
4. 汇总真实独立患者数、访视分布、关键字段覆盖、可用标签和不同窗口支持情况；受控明细与可提交的去标识汇总分开。
5. 提交下一阶段任务选择所需证据，以及 AD 公开临床表的具体补齐清单。此包不训练、不导入业务库、不修改活动模型。

现有自动初筛计数不能直接作为该实施包的最终验收结果。人工核验覆盖、尚未读出的图像信息和不确定标签必须明确。

### 7.2 每阶段统一完成记录

记录输入版本、实际改动、实际执行的验证、结果、失败或跳过、限制、产物位置和下一阶段条件。需要更新本总领文档时保留决策记录；不把待办写成完成，不将无模型可发布写成预测能力已完成。

代码验证遵循 [开发指南](../../DEVELOPMENT.md) 和 [报告运维文档](../../OPERATOR_REPORT_OPERATIONS.md)。涉及 UI 时先完整读取 [设计规范](../../DESIGN_SPEC.md)。数据库、worker、归档和权限行为使用适用的隔离集成验收，不能以 mock 结果代替真实链路。
