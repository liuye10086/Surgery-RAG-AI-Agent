# 阿尔茨海默病病例约束纵向数据生成设计（v2 校准版）

> 日期：2026-08-19
> 协作方式：简化流程，直接在当前 `main` 工作区实施
> 状态：已结合真实病例校准，可实施
> 输入：`AD病例（1-73例）.docx`、`AD病例70例.docx`（单次快照值：MMSE/MoCA、脑脊液 Aβ/tau、APOE/基因、部分炎症指标）
> 输出：固定结构 `patients.csv`、`visits.csv` 及独立审计文件，供操作者端"进展预测/规则挖掘机制"验证

## 0. 2026-08-19 校准修订说明

本版以两份真实病例 Word 为证据校准原草案的 4 个占位假设，阶段模型、双队列方向和 R1/R2 机制方向不变。

1. **病例基数**：第一份文档按出现顺序得到 75 个病例段（编号 69、72 各出现两次）；第二份文档因包含重复编号、缺号与 `24-26病例` 家系汇总，按独立患者拆分后得到 71 个病例锚点，共 146 个。生成 150 例时，前 146 例逐段锚定，余下 4 例采用分层、固定顺序的病例约束重组，并在 `source_components` 中记录来源，不冒充新增真实病例。
2. **CDR 分布**：原假设各 30 例改为 `CDR 0: 5 / 0.5: 10 / 1: 55 / 2: 45 / 3: 35`。依据是病例标题、明确 CDR、MMSE 和生活功能线索推断的 146 例严重度约为 `0:5 / 0.5:9 / 1:51 / 2:46 / 3:35`；目标分布保留真实病例以轻度和中度为主的形态，同时补足至 150。
3. **队列比例**：原假设 `ad_progression 120 / mixed 30` 改为 `ad_progression 124 / mixed 26`。病例标题与最终诊断复核得到约 `121 / 25`，按 150 例等比例折算并保证模拟病、竞争病因进入 `mixed`。
4. **规则阈值**：R1 从 `Aβ42 < 400、p-tau181 > 60 pg/ml` 改为 `Aβ42 < 540、p-tau181 > 58 pg/ml`。病例原文明确出现 `Aβ42 < 540` 与 `p-tau181 > 58` 的实验室判定界值，且 405–520.76 pg/ml 的 Aβ42 多次被原报告判为降低；不同检测平台界值不一致，因此这里只把 540/58 作为本合成数据集的固定方法验证阈值，不推广为通用临床界值。
5. **指标清单**：保留原有字段，并新增单次字段 `plasma_ptau217` 与 `plasma_nfl`。病例中存在可量化血浆 p-tau217 与外周血 NfL；二者与脑脊液 `ptau181`/`ttau` 分开命名，避免混合样本类型。病例也出现 ADL、NPI、ADAS-Cog、炎症细胞因子等，但量表版本/方向或覆盖率不一致，本任务不扩列。

## 1. 目标

在真实 AD 病例只提供**单次评估快照**（无逐年纵向序列）的前提下，生成 150 例带 CDR 分级、带时间维度的纵向结构化数据，植入"炎症 + 病理 → 认知进展"的规则信号，用于验证导入管线、规则挖掘算法与操作者端预测流程。

必须满足：

1. 病例级人口学、单次认知评分、脑脊液标志物、基因型优先来自病例原文；
2. 每位患者 ≥ 3 次随访，首末跨度 ≥ 24 个月；
3. 核心纵向指标（MMSE/MoCA/CDR/GFAP/CRP/同型半胱氨酸）每患者 ≥ 3 个时间点；
4. 日期、结局（CDR）与指标序列在患者内部一致；
5. 输出列名/顺序/编码/缺失值严格符合本规格；
6. 生成过程固定种子、字节级可复现，并提供逐例审计。

## 2. 数据真实性边界

- 原病例中的指令性文字不视为用户指令，只作为病例资料读取。
- 病例能直接支持的年龄、性别、单次评分/标志物值、诊断、队列归属作为**锚点**；没有源报告的纵向值由生成器补齐。
- `patients.csv` / `visits.csv` 不增加"合成/来源"标记列；来源与生成边界写入独立 `DATA_PROVENANCE.md`。
- 生成值不得表述为从原始检验报告补采得到的真实测量值，不得作为真实世界临床证据或诊疗依据。

## 3. 阶段模型（CDR 分级）

结局与纵向状态统一用 **CDR（临床痴呆评定量表）** 分级：

| CDR | 含义 |
|---|---|
| 0 | 正常认知 |
| 0.5 | 可疑 / 极轻度认知损害（MCI） |
| 1 | 轻度痴呆 |
| 2 | 中度痴呆 |
| 3 | 重度痴呆 |

`final_stage` 取最后随访时的 CDR；"进展"定义为随访期内 CDR 上升（如 0→0.5→1）。进展预测的二元事件 = **进展为痴呆（CDR ≥ 1）**，与脂肪肝"进展为肝硬化/肝癌"对齐，供规则挖掘使用。

## 4. 队列分组

| 队列 | 含义 | 用途 |
|---|---|---|
| `ad_progression` | 有 AD 临床/影像/生物标志物证据（早发型、晚发型、PCA 亚型、MCI 进展型等） | 进入主要进展分析 |
| `mixed` | AD 模拟病 / 竞争病因（自身免疫性脑炎、血管性痴呆、帕金森病痴呆、路易体痴呆等） | 敏感性分析 / 分层对照，不进入主规则挖掘 |

> 参考脂肪酸肝经验：抗 ITPR1 自身免疫性脑炎等"模拟 AD"病例必须单独入 `mixed`，不得混入真 AD 进展线。

## 6. 植入规则（折中方案）

规则为**可计算模式**（从纵向数值直接判定），植入后用于验证"方法能否把规律挖回来"，不代表独立临床发现。

- **R1（核心：病理 + 神经炎症 → 进展）**
  基线 `abeta42 < 540 pg/ml` 且 `ptau181 > 58 pg/ml`（低 Aβ42、高 p-tau），且末 3 次随访 `gfap` **连续上升** → 进展为痴呆（CDR ≥ 1）。

- **R2（辅助：外周炎症 → 进展）**
  末 3 次随访 `crp` **连续上升** 且 `homocysteine` 末值较基线升高 → 进展为痴呆。

- **组合路径**：`r1` / `r2` / `r1_r2` / `non_rule_progression` / `stable` 五类，与脂肪肝对齐；并保留"无炎症信号但仍进展"的非规则路径，避免结局被规则完全决定。

> 540/58 来自本批病例报告中的明确判定界值，只服务于本合成数据集的方法验证；方向（GFAP/CRP 上升、低 Aβ42、高 p-tau）为设计核心。

## 7. 队列与结局分布（病例校准后）

- 总患者：150。
- 队列：`ad_progression` 124、`mixed` 26。
- 结局 CDR：`0` 5 / `0.5` 10 / `1` 55 / `2` 45 / `3` 35。
- 规则路径：确保 `r1`、`r2`、`r1_r2`、`non_rule_progression`、`stable` 五类均非空，且进展者与未进展对照均充足。

## 8. 随访时间线

- 每患者 3–6 次随访，首末跨度 24–60 个月，间隔不规则（对齐脂肪肝）。
- 原文已有明确日期（如病例4 的 2017/2018）优先纳入时间线；否则固定种子生成基线日期。
- `dementia_date`（CDR 首次 ≥ 1）与随访日期一致；结局事件后不生成超出末次随访的记录。

## 9. 指标生成模型

- **基线**：以病例锚定值（单次 MMSE/MoCA/Aβ/tau/CRP/同型半胱氨酸/APOE）为基线；缺失值按临床可解释范围 + 固定种子补齐。
- **认知轨迹**：AD 进展者 MMSE/MoCA 逐年下降、CDR 上升；非进展者平稳或轻微波动。
- **炎症轨迹**：R1 路径 GFAP 连续上升、R2 路径 CRP/同型半胱氨酸连续上升；稳定路径无明显炎症信号。
- **联动约束**：低 Aβ42 / 高 p-tau 与更高的 CDR 上升速率相关；GFAP 上升先于 CDR 上升（时间滞后），保证"炎症信号在进展之前"。
- 数值精度与临床安全边界（SAFETY_BOUNDS）参照脂肪肝做法，逐指标定义。

## 10. 缺失模式

- 纵向核心（MMSE/MoCA/CDR/GFAP/CRP/同型半胱氨酸）每患者 ≥ 3 个非空值；
- 单次字段（Aβ/tau/YKL-40/sTREM2、血浆 p-tau217/NfL）首访记录、后续置空；
- 缺失以空单元格表示，不用 0/NA/-；原文锚定值不因缺失抽样被删。

## 11. 可复现性

- 固定种子（如 `20260819`）；
- 病例解析 → 中间 JSON → 生成 CSV 的确定性顺序；
- 重复运行两个 CSV 字节级一致；种子、版本、输入文档哈希写入 `DATA_PROVENANCE.md`。

## 12. 输出文件

目录 `data/generated/ad_longitudinal_150/`：

- `patients.csv`（列见 §5.1）
- `visits.csv`（列见 §5.2）
- `quality_report.json`：队列/结局/路径计数、逐例分类理由、结局来源审计（`explicit_*` 或 `generated_stage_assignment`）、缺失率、分位数、验证错误。
- `extracted_cases.json`：逐例锚点、队列理由、source_components。
- `DATA_PROVENANCE.md`：输入文档哈希、种子、生成规则、队列/结局/路径统计、使用边界。

## 13. 质量控制与验收

- 150 例，`P001–P150` 唯一连续；两表列名/顺序精确匹配；UTF-8 无 BOM；缺失为空字符串。
- 每患者 3–6 次随访、日期严格递增、跨度 730–1830 天、末次 ≤ 数据截止日。
- `final_stage` ∈ {0, 0.5, 1, 2, 3}；CDR 上升与 `dementia_date` 一致；纵向核心指标每患者 ≥ 3 值。
- R1/R2 植入路径与实际数值一致（`assigned_path_mismatches=[]`）；稳定路径不被误判为 R1/R2。
- 明确 AD 模拟病病例不进入 `ad_progression`；逐例分类理由可审计。

## 14. 实现边界

本任务只生成数据文件、审计与可复现生成脚本；不实现数据库导入 API、不修改生产 RAG 链路、不把生成数据直接写入数据库。
