# AI 操作者病例年龄字段设计

日期：2026-09-01

状态：用户已确认设计，待书面规格复核

## 1. 目标

为 AI 操作者端纵向病例增加整数年龄字段，并确保年龄从病例录入、数据库持久化、报告输入快照一直传递到纵向模型特征。

年龄合法范围统一为 `0–120`。该范围同时用于数据库约束、后端请求校验、前端控件和现有训练数据 Schema，避免生产输入与模型数据规范使用不同边界。

本次采用生产兼容迁移：已有病例不填充虚假年龄，迁移后其年龄保持 `NULL`；新建病例必须填写年龄；旧病例仍可查看和执行不涉及年龄的局部更新，但通过前端完整保存或生成新报告前必须补录年龄。

## 2. 方案选择

采用“数据库暂时可空、应用层对新数据必填”的渐进方案：

- `operator_cases.age` 为可空整数列，以兼容服务器中的已有数据；
- 数据库检查约束只允许 `NULL` 或 `0–120`；
- 新建接口要求年龄必填；
- 局部更新接口仅在传入年龄时校验并更新；
- 报告生成入口拒绝没有年龄的旧病例。

不采用以下方案：

- 立即设为 `NOT NULL` 并写入默认年龄：无法从现有数据推导真实年龄，会污染病例和模型输入；
- 数据库与应用层都长期允许缺失：无法保证新报告具备完整年龄特征；
- 使用出生日期：本项只需要当前整数年龄，出生日期会增加不必要的个人信息和日期换算语义。

## 3. 数据库设计与生产迁移

新增 Alembic 迁移 `0013`，以当前 `0012` 为 `down_revision`。升级顺序为：

1. 向 `operator_cases` 增加 `age INTEGER NULL`；
2. 增加命名检查约束 `ck_operator_cases_age_range`：

```sql
age IS NULL OR age BETWEEN 0 AND 120
```

迁移不执行数据回填，也不改变已有行。回滚时先删除检查约束，再删除年龄列。

服务器部署只通过 `alembic upgrade head` 应用该增量迁移，不使用 `schema.sql` 修改现有生产库。`database/schema.sql` 仍同步增加年龄列和约束，但它只作为全新数据库的当前结构快照。

ORM 中 `OperatorCase.age` 与数据库保持一致：`Integer`、可空。只读数据库核查脚本必须检查年龄列及其类型，并在现有约束核查能力允许时检查命名范围约束。

## 4. 后端契约

### 4.1 请求和响应 Schema

- `OperatorCaseCreate.age`：必填整数，`ge=0`、`le=120`；
- `OperatorCaseUpdate.age`：可选整数，传入时必须为 `0–120`；
- `OperatorCaseOut.age`：`int | None`，以便读取迁移前创建且尚未补录年龄的病例。

`PATCH`/更新语义保持局部更新：请求未包含 `age` 时不覆盖数据库现值。显式传入 `null` 不用于清除已经填写的年龄，应由 Schema 拒绝，避免新数据退回缺失状态。

### 4.2 持久化和报告门禁

病例创建服务保存 `payload.age`，更新服务沿用 `exclude_unset=True` 的字段更新方式。

生成纵向报告前检查病例年龄。若年龄为 `NULL`，接口返回 `422 Unprocessable Entity` 和明确的补录提示，并且必须在创建 `AIReport(status="generating")` 记录之前返回，防止产生无法完成的报告任务。

已有病例仍可被查询；后端局部更新接口允许先修改其他字段。只要年龄缺失，任何新报告生成请求都必须被同一门禁拒绝。

## 5. 数据流和模型输入

年龄链路固定为：

```text
前端年龄控件
  -> OperatorCaseCreate/Update
  -> operator_cases.age
  -> build_input_snapshot().case.age
  -> longitudinal feature builder
  -> 模型输入列 age
```

`build_input_snapshot()` 在病例快照中加入 `age`，使报告能够追溯生成时实际使用的年龄，而不是之后修改过的病例年龄。

固定窗口特征构建不再把 `age` 写死为 `None`，而是读取快照病例中的年龄。模型套件的兼容读取可以继续支持历史键 `patient_age`，但必须使用显式 `None` 判断；不能使用 `case.get("age") or ...`，因为合法值 `0` 会被错误地当成缺失。

本项不修改训练数据、不重训模型，也不改变训练制品。现有训练数据 Schema 的 `0–120` 校验保持不变，生产病例输入与其统一。

## 6. 前端设计

在 `LongitudinalCaseEditor` 的病例基本信息网格中增加 Element Plus 整数输入控件：

- 控件使用 `el-input-number`；
- 最小值 `0`，最大值 `120`，精度 `0`；
- 新建病例初始值为空；
- 选择已有病例时回填年龄；
- 保存 payload、页面状态、API 类型和 store 流程均携带年龄。

保存前若年龄为空或超出范围，沿用当前表单错误反馈方式提示用户并停止提交。旧病例可以被选择和查看，但必须补录有效年龄后才能通过编辑器完整保存。报告生成被后端再次校验，前端校验不能作为唯一保护。

本次只在现有病例基本信息网格中增加一个字段，沿用 `docs/DESIGN_SPEC.md` 的变量、间距、断点和 Element Plus 控件风格，不改动页面整体视觉结构。

## 7. 错误处理

- 新建病例缺少年龄或年龄超界：Pydantic 返回 `422`，不写入数据库；
- 更新病例传入非整数、`null` 或超界年龄：返回 `422`，原年龄不变；
- 旧病例年龄缺失时生成报告：返回 `422`，不创建报告记录、不启动 SSE 生成；
- 绕过应用直接写入超界年龄：数据库检查约束拒绝事务；
- 年龄为 `0`：作为合法整数完整持久化和传递，不能被缺失值兼容逻辑替换。

## 8. 测试与验收

实施遵循先失败测试、再实现的顺序，至少覆盖：

### 8.1 数据库契约

- Alembic 只有一个 head，`0013` 正确衔接 `0012`；
- 迁移包含可空整数列和 `0–120` 命名检查约束；
- `database/schema.sql`、ORM、Alembic 与只读核查脚本对年龄字段定义一致；
- 迁移升级不会要求已有病例回填年龄。

### 8.2 后端行为

- 创建病例必须提供 `0–120` 的整数年龄；
- 年龄 `0` 和 `120` 可保存，`-1`、`121`、小数和空值被拒绝；
- 旧病例可读取且输出 `age: null`；
- 局部更新未传年龄时保留原值，传入合法年龄时持久化；
- 输入快照包含生成时年龄；
- 固定窗口和模型套件特征取得年龄，且年龄 `0` 不丢失；
- 缺少年龄时报告生成在写入报告记录前返回 `422`。

### 8.3 前端行为

- API 类型、创建/更新 payload、store 和页面保存链路包含年龄；
- 编辑器能初始化、回填并提交年龄；
- 空值和超界值不能提交；
- 前端契约测试和生产构建通过。

### 8.4 回归验证

- 运行纵向病例、特征、预测、报告、Alembic 和 Schema 专项测试；
- 运行相关前端契约测试与 `npm run build`；
- 运行 `git diff --check`；
- 若全量测试仍受仓库已有的无关收集错误阻塞，应记录该错误，同时保证本项专项测试全部通过。

## 9. 文档完成条件

只有在迁移、后端、前端和专项测试均完成后，才在 `docs/AI操作者流程核查.md` 的数据库附录中将“`operator_cases` 未保存年龄”标记为已解决，并记录以下生产操作边界：

- 代码部署后由 Alembic 将服务器数据库升级到 `0013`；
- 不在服务器上重新执行 `schema.sql`；
- 原有病例年龄为空是预期兼容状态，生成新报告前由操作者补录。

## 10. 不在本次范围内

- 不连接或直接修改服务器数据库；
- 不为已有病例推测或批量填充年龄；
- 不将数据库年龄列立即改为 `NOT NULL`；
- 不改用出生日期或保存其他身份信息；
- 不重训、替换或重新发布纵向模型；
- 不处理保存后自动生成报告、保存 loading 等与年龄无关的现有交互问题；
- 不继续处理数据库附录中的下一项，直到本项通过验收。
