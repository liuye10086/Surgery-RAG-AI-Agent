## 4. 本次发现的额外工程缺口

### 4.1 后端终态与完成事件不一致

`longitudinal_report_generator.py` 的 `_transition_report_from_generating()` 返回是否更新成功，但成功路径忽略返回值，之后仍发送正文和 `done(status=completed)`。

本轮用内存 mock 将条件更新结果固定为 False，实际收到 `stage → prediction → delta → delta → done`，且 done 宣称 completed。这个复现说明：**条件更新保护数据库终态，并未同时保护客户端完成声明。** 新任务协议必须只广播已提交的真实状态，失去执行权的 worker 不得发布结果。

### 4.2 页面完成态与网络读取态混合

`operator.ts` 的 `onDone` 先将 `generating=false`，再异步执行 `fetchReport`；`OperatorView.vue` 此时立即选择 `currentReport.content`。因此代码存在正文尚未加载的显示空档。当前流解析在 EOF 且未收到 done/error 时也没有最终状态核对。此处为代码路径确认，未在本轮执行浏览器故障注入。

### 4.3 证据快照一致不等于展示信息等量

网页将第 8 节 Markdown 替换为结构化证据组件；PDF 校验证据快照，但正文仍读取 Markdown。`render_evidence_markdown()` 没有完整呈现网页的池统计、分项相似度、规则条件与数值解释，且直接输出部分 `available`、性别、阶段、结局状态代码。

应保留单一证据事实来源，并要求正文、网页、PDF 的必需信息一致。第 5 项的数据证据链仍可复用。

### 4.4 模型可加载不等于本次所有输入齐备

readiness 校验基础输入、访视门槛和模型组可加载；各任务真正的特征缺失校验发生于推理特征构造。后者主要返回 `required_feature_missing`，没有保留具体缺失字段。应在实际构造模型输入的同一处记录审计，不在模板里再造一套输入判定。

### 4.5 观察图表需要统一安全边界

网页和 PDF 各自计算图表点位；网页允许缺失 `unit_state` 的旧序列进入后续判断，PDF 要求明确 `consistent`。网页 `Number(null)` 也可能把旧损坏值变为 0。新报告应保存明确的可绘图范围和规范化点集；历史兼容必须保守，不把缺少安全信息当作安全。

### 4.6 当前超时不是整个任务期限

120 秒 `wait_for(to_thread(...))` 只覆盖预测阶段；线程超时并不能硬终止底层计算。模型加载、证据与数据库等阶段需要自己的期限及全任务上限。进程崩溃前未落终态也没有持久巡检修复。

## 5. 架构方案比较

| 方案 | 优点 | 局限 | 结论 |
|---|---|---|---|
| A. 类型化报告文档 + PostgreSQL 持久任务 + 独立 worker | 复用现有数据库；能原子入队、查询、取消、租约与终态；无需新增消息服务 | 需要任务表、worker 监督、迁移和恢复测试 | 推荐，适合当前部署规模 |
| B. 类型化报告文档 + 外部消息队列/worker | 适合已有消息基础设施或大量分布式任务 | 新增服务、权限、备份、消息与数据库一致性处理；当前仓库未发现可直接复用的队列 | 可作为未来扩展，不作为本次默认 |
| C. 只补 Markdown + 请求内生成 + 超时清理 | 改动较少 | 请求与任务耦合，刷新后生命周期难以可靠处理，不能完整覆盖已确认验收 | 不推荐 |

用户已批准以下方案 A。任务调度与报告内容分成两个可独立验收的模块，但共同构成第 6 项，不能只交付其中一个就宣布完成。

## 6. 完整报告的唯一结构化契约

新增 `ReportDocument v1`，作为新报告的**展示事实快照**。预测 v3 与证据 v1 保留各自职责，不为了模板修改就升级或重算模型结果。

建议在 `ai_reports` 增加可空 `report_document` JSONB、`report_document_sha256` 和 `generation_fingerprint_version`。旧报告为空，走旧读取路径，不回填。新报告的文档、正文、预测、证据和完成状态同事务保存。

文档组成：

| 区块 | 固化内容及规则 |
|---|---|
| identity | schema/template 版本、报告 ID、批次 ID、匿名编号、创建时间、预测锚点日期、病种、年龄、性别和阶段；只有匿名编号充当病例标识 |
| generation_context | 模型组 ID/哈希、数据 release/清单哈希、标准 token、目录版本与本报告使用的显示标签、最低访视门槛；历史不读取当前目录 |
| summary | 观察是否可描述、各任务输入是否满足、模型实际参与数量、证据状态、信号数与主要局限；“可描述观察”与“可用于模型推理”分开 |
| data_quality | 类型化问题列表及逐任务输入检查；来源、严重程度、稳定原因码、指标/访视/字段定位、影响与建议复核动作 |
| observations | 全部访视、指标、日期和经批准展示的上下文；首末值、绝对/相对变化、缺失状态、可比较状态、可绘图状态 |
| model_runs | 每个实际选择的结局/阶段/趋势任务：身份、目标、期限、执行状态、中文原因、校准与审计声明、字段输入审计 |
| evidence | 引用已固化 EvidenceBundle 的 ID/哈希；将必需展示字段按确定性格式纳入报告内容，不重新检索或计算相似度 |
| review_items | 按严重程度与访视顺序稳定排序、去重的问题清单；“核对什么、为什么、影响什么、定位哪里” |
| limitations | 逐任务与逐证据限制及总体用途边界；事实未知显示“未记录”，禁止猜测训练样本数量或比例 |
| presentation | 已确定的中文标签、展示状态、章节 ID 与图表点集；前端只负责排版/交互，不能重新裁定质量和信号 |

### 数据质量与模型输入审计

- 复用校验器；不新增一套疾病核心指标常量。模型必需/允许缺失字段来自本次固定 metadata，标准条件来自本次 EvidenceBundle。相似度的核心指标不能自动等同模型必需输入。
- 在实际模型输入构造处输出审计：有序字段名、构造成功状态、缺失必需字段、允许缺失字段、已配置插补策略、实际送入模型容器的字段与规范化输入哈希。
- 元数据允许字段缺失时，写“缺失，由模型管道按配置处理”；只有确实捕获插补后值时才能说“已使用某插补值”。不得凭估计填入插补数值。
- 输入审计覆盖所有选中任务，不只覆盖出现关键信号的指标；模型没有被调用时不能写“实际已使用”。
- 模型合成数据标记、临床有效性和校准逐模型保存；当前 warnings 是模型组汇总，不能反推逐任务训练组成。
- 新报告的年龄/性别/阶段缺失、非法单位等继续在生成前阻断；不要为了展示复核项而放松第 3 项写入门。历史缺项只作只读提示。
- 标准上下文不足、指标有效观察不足、允许缺失输入、部分任务失败、无合格参考病例等形成不同问题；无合格参考病例不冒充病例查询故障。

### 观察事实与图表

- 总览表加相对变化，按已经保存的比例格式化为百分比；首次值为 0 时写“首次值为 0，不计算百分比”。单位冲突/缺失时禁止输出跨单位变化与趋势线。
- 每次访视完整列出日期、指标中文名/代码、数值、单位；遗漏写“本次未记录”，不填 0、不跨访视前向补值。
- 提供检测来源、方法、设备、样本、治疗/诊断变化等上下文；AD 追加量表版本、语言、教育与校正，脂肪肝追加影像类型。
- 备注按“操作者录入，未由模型验证”显示，仅作上下文，不生成新的医学解释。自由文本作为纯文本安全转义；模型审计和日志不复制备注。
- 图表使用实际日期间隔，显示日期、数值和单位；数量阈值读取固化的信号/展示规则，不和报告准入门槛混用。
- 新报告仅绘制明确可比较且达到有效观察门槛的序列；单位状态未知或非有限值只展示可读表格与原因。网页/PDF 使用同一语义点集。

## 7. 11 章交付合同

| 章节 | 必须展示 |
|---|---|
| 1 报告摘要 | 可用观察、实际模型参与、证据完整性、优先复核事项、当前模型用途限制；不单凭访视数写“数据够用” |
| 2 病例与预测范围 | 报告/匿名编号、生成时间、年龄/性别/基线阶段、观察起止、锚点与预测截止；明确具体结局 |
| 3 数据质量与适用性 | 逐问题和逐任务输入契约；缺失、允许插补、上下文不足及影响 |
| 4 已观察到的纵向变化 | 全指标总览、完整逐访视表、真实日期图、检测上下文；均明确为观察事实 |
| 5 未来 365 天进展风险 | 本次具体结局任务、分数语义、等级及版本化阈值依据、校准状态、参与/未参与原因；不称临床概率 |
| 6 阶段与下一访视趋势 | 阶段模型候选及分数；每个趋势模型独立状态；下一访视方向不表述为 365 天数值预测 |
| 7 关键进展信号 | 仅消费已有信号解释，保留来源定位、模型特征关系和贡献不可用说明；不创造特征贡献分值 |
| 8 标准与参考病例 | 文档/版本/定位/原文、规则适用性及解释、病例池统计、相似度覆盖与分项、匿名参考结局、证据限制 |
| 9 不确定性与局限性 | 训练构成已知事实、合成限制、校准、证据条件和输入缺项；没有限制数据不等于没有限制 |
| 10 人工复核重点 | 有定位、有影响、有动作的结构化清单；不自动给用药或治疗建议 |
| 11 技术追溯附录 | 模板/文档版本、批次、模型/数据/标准/目录身份、哈希、输入字段审计和技术原因码 |

主阅读区使用中文；技术代码可在第 11 节伴随中文解释出现。未知状态显示“状态未识别，相关结果不可用”，不能原样把内部枚举当作解释。

结局预测锚点使用输入快照的最后一次有效访视日期，365 天截止日期从该锚点计算；报告生成时间独立展示，不能以下载/生成当天替代预测锚点。年龄明确为病例录入的年龄，不根据报告打开时间自动增长。

脂肪肝的结局随基线阶段选择“进展为肝硬化或肝癌”或“肝硬化后发生肝癌”；AD 使用已有相应结局任务。AD evidence-only 不转成数值诊断阈值，CDR 观察不等同独立诊断。上述文字须从现有任务/标准契约映射，不在模板里另行定义医学规则。

## 8. 持久生成任务与恢复设计

### 8.1 状态分层

保留 `ai_reports.status` 的四个值：`generating/completed/failed/cancelled`，避免无谓改变已完成历史合同。

新增 `report_generation_jobs`：一份新报告对应一个任务，内部状态 `queued/running/completed/failed/cancelled`，另有阶段、版本递增的 revision、时间戳、租约 owner/token、租约截止、总期限、取消请求和安全错误码。排队在页面显示“等待生成”，运行显示具体阶段；两者映射报告的 generating。

任务身份以 `report_id` 关联报告，不能只依赖可删除的 `operator_case_id`。来源病例归档/删除后，已受理任务仍按固定快照运行。新建仍执行病例权限与状态门禁。所有查询/取消/订阅以报告所有者校验，越权统一 404。

### 8.2 受理、幂等与版本固定

1. 新受理接口建议 `POST /operator/longitudinal-cases/{case_id}/report-jobs`；使用 `Idempotency-Key`，返回 202、report_id、batch_id、status_url、events_url。
2. 幂等作用域为用户与请求 key；同 key 同请求返回同一报告，同 key 不同请求 409。先检查已受理 key，再读取当前病例，防止病例后来变化使网络重试被误认为新任务。
3. 新请求按病例锁校验权限、状态、输入与标准；固定模型组、活动数据/目录和标准身份。一个生成上下文的身份读写必须一致；指针在受理期间切换时重新校验或失败，不拼接不同批次版本。
4. 用同一事务保存报告初始快照、任务与幂等记录，提交成功才返回受理成功。不得先返回再做 best-effort 入队。
5. 同一病例最多一个活动任务；第二个不同 key 请求返回冲突并提供当前用户可见的已有 report_id。新任务容量在事务内检查；初始建议全局待执行上限 20、每账号活动任务上限 2，超限 429，可配置。
6. worker 按固定 ID/哈希加载；不再读取 active 决定实际模型。任务等待期间模型切换不会改变已受理报告；固定文件不可用或哈希变更则失败关闭。
7. 标准后续更新不能让已受理任务默默改用新标准；被撤销或完整性不满足则失败，不能伪装为原版本成功。参考查询故障继续复用第 5 项部分证据降级规则。

### 8.3 Worker、租约和期限

- 独立入口 `python -m app.workers.report_worker`，通过 PostgreSQL 行锁和 `SKIP LOCKED` 领取任务；领取事务短，不跨模型计算持锁。
- 初始并发为 1，依据现有阿里云运行手册约 4 GiB 内存制定；仅加载所需预测模型，不启动聊天/RAG/BGE-M3。并发提升前实际测量内存与吞吐。
- 建议初始运行参数：心跳每 10 秒，租约 45 秒，巡检每 15 秒；排队最长 10 分钟；运行总上限 300 秒，模型加载 60 秒、模型推理 120 秒，阶段期限还受剩余总期限约束。均配置化并在上线压测校准。
- 模型执行放入可终止子进程，主 worker 维护租约/取消/期限；不能把 `to_thread` 超时当作停止计算。子进程不持有跨进程复用的数据库 session。
- 所有结果提交必须满足 job=running、租约 token 匹配且未取消/未过期，并在同事务将 report/job 变为一致终态；失效 worker 结果直接丢弃。
- 定时巡检将过期 running 收敛为 failed（中文“生成服务中断，请重新生成”）；已请求取消的任务收敛为 cancelled；排队超时收敛为 failed。queued 未超时可由重启后的 worker 正常领取。
- **本期不自动重跑已经执行中断的预测。** 自动恢复指可查询、清理遗留状态和继续尚未执行的排队任务；中断后用户再次生成新报告，保留旧失败记录。该保守策略已随设计整体获批。
- 多 worker/多次巡检重复执行不重复改终态；“仅一次结果发布”以数据库条件提交保证，不宣称物理计算恰好执行一次。
- 进程停止后由部署监督重启 worker，再按数据库期限巡检；监督服务自身停机时不能承诺仍能及时收敛，必须告警。

### 8.4 查询、SSE、刷新和取消

- `GET /operator/reports/{id}/generation-status` 返回轻量持久状态、阶段、revision、更新时间和安全错误；不重复返回大快照。
- `GET /operator/reports/{id}/events` 使用现有 Bearer 鉴权 fetch 流；每次连接先发送当前持久状态，再发送更高 revision。SSE 是状态通知，不是任务执行入口，不要求重放逐字 delta。
- 浏览器断线或 EOF 未读到终态时查询状态，先 2 秒、5 秒、之后最多每 10 秒退避轮询；恢复连接/窗口重新聚焦时刷新；关闭组件停止订阅和轮询。
- 路由保存 report_id，刷新后重新授权查询；先显示数据库状态，不把本地残留内容当作完成报告。
- `POST /operator/reports/{id}/cancel` 是唯一显式任务取消操作。关闭页面、返回病例、AbortController 断开订阅均不取消任务。取消与完成竞争由数据库事务决定，已经完成的报告不能被取消覆盖。
- 完成时先取回通过完整性检查的保存详情，再显示“已完成”；读取失败显示“报告已生成，加载失败，可重试”，不再次提交生成请求。
- 同一个 report_id/batch_id/revision 隔离事件，旧任务的响应不得覆盖新病例/新报告。
- 原 POST SSE 入口保留兼容适配期，但所有生成必须委托同一任务服务；不得留下可绕过任务和幂等控制的旧执行路径。旧客户端未给 key 的新旧重试无法保证幂等，发布窗口需强制前端更新并记录兼容期终止条件。

## 9. 保存、完整性与历史兼容

- 新文档 canonical JSON + SHA-256；记录 `report_document.v1` 与固定模板版本。
- 新指纹版本 v2 纳入输入快照、预测、证据、报告文档和正文哈希；不要把最终指纹放进正文再计算自身。正文可列输入/证据哈希，最终整体指纹由详情元信息展示。
- 旧指纹无版本或 v1 继续按原算法验证；未知新版本失败关闭，不回退为“旧报告不可验证”来绕过校验。
- 正文、文档、预测、来源投影、证据和完成状态在同事务发布；sources 继续是 EvidenceBundle 派生投影，发布前断言一致。
- 历史 v1/v2/v3 没有新文档时读取原 content 和已存结构化数据；不使用新模板补写、不查询当前目录补中文、不从当前病例补人口学信息。
- 模板更新只影响新生成报告。网页主内容和 PDF 均读取保存正文；交互证据组件与图表只展示文档已固化的内容，必需信息不能仅在网页存在。
- PDF 视觉排版可随维护改进；本项保证历史事实与文字不重算，不承诺每次 PDF 二进制逐字节相同。如将来要求版式也永久封存，应增加独立归档文件机制。
- 新报告完整性异常时网页显示明确异常提示并禁用正常结果阅读/下载；旧缺少指纹仅显示不可验证，不伪装为篡改。
- 生成中的新报告禁止删除；应先显式取消至终态再按现有删除权限删除，防止 worker 在报告消失后继续工作。

## 11. 必须通过的验收矩阵

### 11.1 报告内容

- 两病种完整病例：11 章唯一、匿名人口学信息完整、任务结局准确、观察与预测区分、模型限制明确。
- 10 次访视 × 每次 30 个指标、最长允许上下文：全部明细保留，网页不截掉数据，PDF 不裁切表格或出现超大不可分页块。
- 指标缺测、首次值 0、部分指标仅 1/2 次观察、不等日期间隔：无补 0/伪百分比/错误等距时间含义。
- 非法单位与缺少人口学数据仍在新写入/生成前拒绝；旧脏数据安全展示，无跨单位走势。
- AD 缺量表版本/方法/样本等：按已保存标准输出具体受限条件，不能新增诊断阈值。
- 结局成功/阶段失败/单趋势失败组合：逐任务输入审计与页面/正文一致，保留成功任务，不虚构失败任务结果。
- 无合格参考病例、可比性不足、查询故障、标准完整性故障分别验收；前三者按既有合同降级，最后一项阻断。
- 正文、网页证据组件和 PDF 的必需字段集合一致；技术枚举仅在附录伴随解释出现。

### 11.2 任务与故障

- 同 key 重试返回同 report_id；不同请求同 key 冲突；并发点击/双标签页只能得到一个同病例活动任务。
- 创建事务失败不遗留孤立 report/job；受理响应丢失后重试不会重复执行新任务。
- 页面刷新、断网、SSE EOF 无终态、乱序/重复事件、完成后详情加载失败都有明确恢复路径。
- 杀死 worker、杀死模型子进程、运行超时、排队超时：在配置期限内进入可解释终态；恢复后 queued 可继续领取。
- 两个 worker 抢同任务、旧租约晚返回、完成与取消竞争：只有一个终态发布者；条件更新失败不得发送 completed。
- 数据库断连/提交结果不确定：先恢复后读取真实持久状态，不能凭异常猜测失败并覆盖已完成记录。
- 任务受理后病例修改/删除、active 模型切换、标准更新：仍使用固定上下文或按明确原因失败；不得混用新输入、新模型。
- 只读状态/SSE/取消/下载跨账号访问均拒绝；日志没有病例数值、备注、访问 token、模型绝对路径或 traceback。

### 11.3 兼容与上线

- 老报告正文/快照/原指纹不变；旧病例删除、疾病停用后继续只读；未知文档/指纹版本受控处理。
- 使用真实 PostgreSQL 验证 JSONB、唯一/部分索引、事务、行锁领取、租约与双终态条件更新；mock 测试不能代替。
- PC 浏览器完成脂肪肝与 AD 全流程；逐页检查普通和极限长度 PDF 的中文字体、分页、表格与日期图。
- worker 启停、无 worker、积压、过期任务可监测；日志只记录报告/批次/任务 ID、阶段、原因码与耗时。
- 上线先备份与只读预检，按实际 head 迁移，再执行标准/参考窗口准备、postflight、集成/E2E/PDF、worker 故障演练。
- 当前工程门禁与未来模型临床有效性验证分别记录；完成本项不能把无临床有效性声明模型改称临床可用。
