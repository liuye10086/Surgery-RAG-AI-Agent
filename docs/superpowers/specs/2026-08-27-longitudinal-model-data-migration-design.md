# 旧模型与数据迁移到当前 main 并恢复全链路更新能力——设计

日期：2026-08-27
状态：已获用户批准，待用户复核书面规格
范围：仅脂肪肝与阿尔茨海默病（AD），仅电脑端，不进入 P1，不扩展为通用多疾病模型管理平台

## 1. 背景与目标

当前 `main` 已完成 P0-01 至 P0-07，具备 AI 操作者纵向病例与访视、结构化预测报告、报告持久化、历史报告和 PDF 能力。当前正式纵向 registry 没有可用 release，因此报告对未来模型结果安全降级。旧临时成果包含三个未来 365 天结局模型，但存在训练文件哈希绑定错误、实际生成代码状态无法完全由记录的 Git commit 复现、训练/评估流程未完整实现锁定测试集等问题，不能直接发布。

历史代码还保留了阶段标签、趋势方向标签、趋势训练行和可插拔推理接口等零件，但未发现能由当前 registry 安全发布的阶段或趋势模型 artifact、完整 metadata 和评估结果。

本任务一次完成脂肪肝与 AD 的可持续更新链路：

```text
原始数据
→ 数据清洗与特征生成
→ 版本化训练数据集
→ 患者级训练/验证/锁定测试划分
→ 结局、阶段、趋势模型训练与评估
→ artifact、metadata、evaluation
→ 疾病级 release set registry
→ 在线推理
→ 完整纵向报告
→ 数据库存储
→ 历史报告
→ PDF
```

最终目标是 AI 操作者对脂肪肝和 AD 新病例生成内容完整的预测报告，报告同时包含：

- 未来 365 天结局模型结果；
- 下一疾病阶段模型结果；
- 下一次访视关键指标趋势方向模型结果；
- 已观察事实、参考标准解释、模型预测之间的明确边界；
- 模型缺失或异常时的分模型安全降级。

## 2. 明确范围

### 2.1 纳入范围

- 脂肪肝与 AD 的数据生成、质量审计、特征、划分、训练、评估和发布；
- 三个未来 365 天结局任务；
- 脂肪肝与 AD 各自的下一阶段模型；
- 两种疾病关键指标的下一次访视趋势方向模型；
- artifact、metadata、evaluation 的强绑定；
- candidate、review、release set、原子切换、停用和回退；
- AI 操作者在线推理、报告正文、数据库持久化、历史与 PDF；
- 当前 P0 报告、旧 progression API 和电脑端前端回归保护。

### 2.2 不纳入范围

- P1 或移动端；
- 支持任意疾病的通用 MLOps 平台；
- 独立模型管理后台、流量分配、自动定时训练或远程模型服务；
- 未经评估的未来精确指标数值和预测区间；
- 将模型预测写回为患者确诊事实；
- 使用 LLM 生成模型事实、临床结论或训练标签；
- 自动上线、commit 或 push；
- 未经单独批准的数据库 schema 或 Alembic migration。

## 3. 当前事实与迁移决策

### 3.1 旧成果

最完整旧候选位于 `.tmp/p005-verification-20260826-155121/`，包含 P0-03 数据导出、三个结局 candidate、临时 review/release registry 和 smoke 证据。旧成果仅作为回归基线，不进入正式生产 release。

三个旧模型为：

- `fatty_liver.pre_cirrhosis_to_progression`；
- `fatty_liver.cirrhosis_to_hcc`；
- `ad.pre_dementia_to_dementia`。

它们均为未校准逻辑回归，分数语义为 `model_score`，不得称为临床概率。

### 3.2 不能直接发布旧 registry 的原因

- 三个 metadata 的 `training_file_sha256` 错误地共同指向 AD 的 `real_audit.jsonl`；
- `code_version` 不能完整复现实际生成时未提交的代码状态；
- 没有完整执行并保存独立锁定测试集评估；
- 脂肪肝两个任务没有共享疾病级患者划分；
- evaluation 没有完整进入正式 artifact 契约；
- 当前 registry 缺少疾病级原子切换和正式回退能力。

### 3.3 阶段和趋势成果状态

- 阶段：存在阶段标签和结构化输出契约，但未发现正式训练、评估和 artifact 成品；
- 趋势：存在方向标签、训练行、推理接口和测试基础，但未形成完整训练、评估、metadata 和 release；
- 本任务复用这些已有零件，补齐完整生命周期，不把计划或助手函数误认为已发布模型。

### 3.4 数据性质

- 脂肪肝前 150 例为病例文档约束、固定规则补全的合成纵向数据；
- AD 前 150 例以真实病例快照为锚点，纵向过程主要由规则生成；
- P151 至 P300 为固定种子的分层重组合成扩展；
- P0-03 中的 `real` 只表示相对于扩展集的基线部分，不代表真实世界历年临床随访；
- 可用于流程验证和演示，不得声明真实世界临床有效性。

## 4. 总体架构

### 4.1 训练面与在线面分离

训练面负责数据读取、数据集生成、患者划分、训练、评估和发布。在线面只加载已审核且已启用的不可变 release set，不在请求过程中训练或调整模型。

AI 操作者手工录入的病例只用于该病例报告，不自动进入训练集。未来吸收新数据必须经过匿名化、数据质量检查、明确批准和重新训练。

### 4.2 疾病级完整模型组

每种疾病发布一个不可变 release set，而不是逐个模型随意启用。

脂肪肝 release set 包含：

- 两个未来 365 天结局模型；
- 一个下一阶段模型；
- 各关键指标趋势方向模型；
- 数据版本和统一患者划分；
- 全部 evaluation、artifact、metadata 和哈希链。

AD release set 包含：

- 一个未来 365 天结局模型；
- 一个下一阶段模型；
- 各关键指标趋势方向模型；
- 数据版本和统一患者划分；
- 全部 evaluation、artifact、metadata 和哈希链。

一次报告在开始生成时固定一个 release set 身份，生成过程中不得混用不同版本。

## 5. 数据来源、版本与隐私

### 5.0 合成演示训练补充边界（2026-08-27 已批准）

现有可追溯纵向数据无法覆盖全部阶段和趋势类别，尤其 AD 的血浆 NfL 与 p-tau217 仅有首访值。经用户明确批准，允许生成一个独立的 `synthetic_demonstration` 数据 release，用于完成 AI 操作者到完整预测报告的电脑端功能演示和全链路验收。

- 该 release 不替换、覆盖或冒充 `real_only` 数据；训练文件使用独立的 `demonstration_train.jsonl` 和 `demonstration_timelines.jsonl`。
- manifest 必须记录固定种子、生成器版本、数据内容哈希、疾病级 split 哈希、`clinical_validity_claim=false` 和 `training_and_evaluation_for_demonstration_only`。
- artifact metadata 必须记录 `synthetic_in_formal_metrics=true`、`synthetic_purpose=demonstration_training_only`、`leakage_status=review_required` 和 `clinical_validity_claim=false`。
- `synthetic_demonstration` release 只作为训练、评估和模型追溯资料随 registry 发布，不得导入 `case_records` 或作为相似病例证据；本次生产切换不改变正式病例数据 release。
- 首次启用 v3 release set 时若此前没有 v3 活动指针，回滚必须写入可审计的 inactive 指针并恢复旧 registry 兼容路径；不得靠删除活动指针或模型文件完成回滚。
- 任何未显式声明该档位的合成训练样本继续被拒绝；默认 `real_only` 构建行为不变。
- 模型输出只能称为 `model_score`，不得称为临床概率；报告不得把演示预测写成观察事实、标准解释或临床结论。
- AD 阶段和脂肪肝阶段在线推理应用单调约束，不允许预测阶段早于当前已知阶段；相同阶段统一呈现为“维持当前阶段”。
- 该 release 是否进入正式运行目录，仍受生产切换再次审批门控制。

每次生成使用唯一 `run_id`，manifest 至少记录：

- 当前 Git commit 和工作树状态说明；
- 数据生成、特征和训练配置版本；
- 随机种子与关键依赖版本；
- 数据逻辑名称、疾病、生成时间和来源类别；
- 上游来源的匿名 ID 和 SHA-256；
- 每个输出文件的独立 SHA-256；
- 数据内容整体 SHA-256；
- 数据规模、阳性/阴性/不可估计数量；
- 合成数据比例、允许用途和禁止用途。

产物不得包含：

- 可识别患者姓名、身份证号、手机号等身份信息；
- 数据库 URL、密码、密钥；
- 本机绝对路径；
- traceback；
- 外部原始病例文档内容或可识别文件名。

现有 `source_document` 在训练和发布产物中改为匿名来源 ID 或哈希。原始 DOCX 不复制到 registry、模型 bundle 或 Git。

## 6. 数据更新与数据库边界

### 6.1 数据集更新

新数据版本不直接覆盖旧版本。数据生成输出使用版本化目录，旧版本保留为只读回归依据。活动数据版本通过显式配置或版本记录选择。

### 6.2 数据库更新

优先在现有 schema 下使用 `case_metadata` 的版本字段区分数据逻辑名称、数据版本、生成批次、来源哈希和合成状态。导入采用幂等签名，不将同一版本重复插入。

正式更新顺序：

1. 生成数据库完整备份并记录备份校验信息；
2. 在同一事务中导入或切换新版本；
3. 核对疾病、患者、访视、来源版本和汇总数量；
4. 失败则事务回滚；
5. 必要时使用已验证备份恢复。

不直接覆盖用户创建的 `OperatorCase`、访视或历史 `AIReport`。如无法在现有 schema 下可靠完成版本化，停止实施并先取得 schema/Alembic 修改批准。

## 7. 数据划分与泄漏防护

### 7.1 统一患者级划分

脂肪肝和 AD 分别生成固定、可复现的患者级：

- 开发训练集；
- 开发验证集；
- 锁定测试集。

同一患者的所有访视、时间前缀、结局样本、阶段样本和趋势样本只能属于同一集合。脂肪肝两个结局任务共享同一疾病级患者划分。

划分文件保存匿名 `group_id`、集合名称、生成策略、随机种子和 SHA-256，不保存患者直接身份。

### 7.2 锁定测试集

- 模型选择、特征选择、阈值选择和超参数选择只能使用开发训练/验证数据；
- 配置冻结后，锁定测试集只执行一次最终评估；
- 锁定测试结果不得反向用于调参；
- 发布模型是否使用全部开发数据重新拟合必须由固定策略声明，且不能改变锁定测试评估的独立性。

### 7.3 泄漏审计

自动审计至少覆盖：

- 患者或来源家族跨集合；
- `as_of` 之后的访视进入特征；
- 结局日期、最终阶段、标签、未来字段进入特征；
- AD 的 CDR 或量表字段近似复制阶段标签；
- `source_dataset`、患者标签、分组 ID、原文档字段进入模型；
- 合成扩展与来源病例的近重复跨集合；
- 同一患者在不同模型任务中的集合不一致。

审计失败时 artifact 状态为 `blocked`，不得进入 review。

## 8. 特征契约

训练和在线推理共用同一特征生成实现。每个模型 metadata 记录：

- feature schema/version；
- 有序特征名称及其 SHA-256；
- 数值、分类、必需和允许缺失特征；
- 缺失值处理；
- 输入容器；
- 单位和指标别名规范；
- 模型特有的目标、时间窗口和路由条件。

在线特征名称、顺序、版本、必需字段或单位契约不匹配时，该模型返回 `incompatible`，不得尝试猜测或自动补齐结果。

## 9. 模型设计

### 9.1 未来 365 天结局模型

任务：

- 脂肪肝未肝硬化 → 肝硬化或 HCC；
- 脂肪肝肝硬化 → HCC；
- AD 痴呆前期 → 痴呆。

候选模型限定为当前可稳定部署、可审计的模型族，例如逻辑回归和随机森林。选择依据来自开发验证，并与简单基线比较。

评估至少包括 ROC-AUC、PR-AUC、Brier、灵敏度、特异度、混淆矩阵、阈值来源、类别支持数和基线比较。未通过独立校准验证时，输出语义必须是 `model_score`，不得称为概率。

### 9.2 下一疾病阶段模型

脂肪肝候选阶段：维持当前阶段、肝硬化、HCC。
AD 候选阶段：维持当前阶段、MCI、痴呆。

目标标签定义为明确预测窗口内到达的下一阶段或维持当前阶段，不允许把当前阶段或最终阶段字段直接复制为答案。模型输出：

- 当前阶段；
- 最可能下一阶段；
- 候选阶段及模型分数；
- 预测窗口、模型版本和可估计状态。

评估至少包括宏平均 F1、平衡准确率、混淆矩阵、有序阶段误差、各阶段支持数和多数类基线。类别支持不足、标签无法可靠构造或泄漏风险未解决时，不得发布该阶段模型；必须保留明确不可估计证据。

### 9.3 下一次访视趋势方向模型

脂肪肝关键指标：ALT、AST、GGT、TBIL、ALB、PLT、AFP。
AD 关键指标：MMSE、MoCA、CDR、血浆 NfL、血浆 p-tau217。

输出方向为 rising、stable、falling 或不可估计。方向标签由相邻下一次真实访视按指标专属、版本化容差生成；下一次访视值不得进入输入特征。

特征至少评估：首次值、最近值、变化量、变化比例、时间斜率、观察次数、观察跨度、距上次访视时间、缺失比例、当前疾病阶段和允许的历史指标。不得只依赖当前值。

评估至少包括宏平均 F1、平衡准确率、三分类混淆矩阵、各类支持数和多数类基线。只有方向模型通过评估时才输出未来方向。本任务不输出未来精确数值和预测区间，`direction_only` 必须携带 `projected_value=null` 和 `prediction_interval=null`。

## 10. artifact、metadata 与 evaluation

每个模型 bundle 至少包含：

```text
model.joblib
model.meta.json
evaluation.json
```

metadata 绑定：

- artifact 类型、疾病、任务、目标和窗口；
- feature contract；
- dataset manifest、实际训练文件和患者划分 SHA-256；
- evaluation SHA-256；
- model artifact SHA-256；
- 模型族、版本、训练配置和随机种子；
- 代码 commit 与工作树来源说明；
- Python 和关键依赖版本；
- 分数语义和校准状态；
- 合成数据说明；
- `clinical_validity_claim=false`。

registry 验证必须回到 manifest 核对 `training_file_sha256`，不能只验证字段格式。artifact、metadata、evaluation 任一缺失或哈希不一致，均拒绝加载。

## 11. registry、切换与回退

### 11.1 生命周期

```text
训练输出
→ candidate
→ 静态契约和模型加载检查
→ 人工 review
→ 不可变 disease release set
→ 预加载 smoke
→ 原子切换活动指针
```

训练命令不得自动 review、enable 或覆盖生产文件。

### 11.2 疾病级 release set

release set 记录该疾病全部必需模型、bundle 哈希、数据版本、划分版本、评估摘要和审核身份。线上只解析当前活动 release set，不从目录中任意挑选第一个文件。

### 11.3 原子切换

切换前在独立对象中完成：

- 全部文件存在性和哈希检查；
- metadata/任务/特征契约校验；
- 模型反序列化；
- 双疾病或单疾病 smoke；
- 报告结构验证。

通过后只原子替换一个活动指针。旧 bundle 和旧 release set 不覆盖、不删除。

### 11.4 回退

回退是将活动指针原子切回上一已验证 release set。脂肪肝与 AD 分别发布和回退。回退不修改历史报告，也不覆盖旧 progression 模型。

若某疾病完整模型组的强制成员缺失，release set 不得启用。具体关键趋势指标因训练支持不足而无法发布时，必须在 review 前由评估证据明确列为不支持项，并由用户决定是否接受该疾病 release set；系统不得静默省略。

## 12. 在线推理与安全降级

生成报告时：

1. 保存病例和访视输入快照；
2. 识别疾病并固定活动 release set；
3. 根据当前阶段路由结局任务；
4. 分别生成结局、阶段和趋势模型输入；
5. 分别执行模型并保存每个模型的 runtime status；
6. 解释已观察信号和适用标准；
7. 生成结构化预测结果；
8. 从结构化结果渲染正文；
9. 保存正文、预测结果、证据、输入快照和 release set 身份。

安全降级按模型隔离：

- 单个趋势指标异常不影响其他趋势、阶段或结局模型；
- 阶段模型异常不影响结局和趋势；
- 结局模型异常不影响已观察事实、阶段和趋势；
- 模型缺失、metadata 错配、特征不兼容、加载失败或推理异常均不输出该模型预测；
- 错误响应不得包含 traceback、绝对路径、数据库信息或内部模型对象。

## 13. 结构化预测与报告内容

新的预测 schema 在保持 v1/v2 历史兼容的基础上，明确保存：

- disease 和 observation；
- outcome prediction 和对应 model status；
- stage projection 和对应 model status；
- 每个指标的 trend prediction 和独立 model status；
- progression signals；
- evidence、warnings；
- disease release set ID、数据版本和模型版本。

报告固定区分：

1. **已观察事实**：来自保存的真实输入快照；
2. **未来 365 天结局预测**：仅来自结局模型；
3. **下一疾病阶段预测**：仅来自阶段模型；
4. **下一次访视趋势预测**：仅来自趋势模型；
5. **标准解释和相似病例**：只作适用性与证据说明。

不得把参考范围异常写成模型结论，不得把模型分数写成已观察事实，不得把未校准分数称为临床概率。CDR 作为观察指标时必须与阶段模型结论分开。

## 14. 持久化、历史和 PDF

生成完成后 `AIReport` 保存：

- 完整 Markdown 正文；
- 结构化预测结果；
- 输入快照；
- 标准和相似病例快照；
- release set 与模型身份；
- 报告状态和生成时间。

历史报告正文不得重新计算。查看历史时不得重新运行模型、特征、标准匹配或相似病例检索。病例修改、模型更新或标准更新均不能改变旧报告。

PDF 只使用保存正文和保存的结构化预测结果，不重新推理。旧模型生成的旧报告永久保持原内容，新 release set 只影响切换后新生成的报告。

## 15. P0 与旧 API 兼容

- 旧 `fatty_liver_progression_model.*` 和 `ad_progression_model.*` 继续只服务旧 `/progression-predictions`；
- 新 registry 不读取、覆盖或重命名这两个旧模型；
- P0-06 观察信号、参考标准和相似病例继续保留；
- P0-07 报告章节、历史持久化和 PDF 行为继续兼容；
- 旧 v1/v2 `prediction_result` 仍可查看和下载；
- 新模型只影响新生成报告。

## 16. 电脑端展示

不重新设计整体页面，不做移动端。

## 17. TDD 实施与验证

设计文档批准后先编写详细实施计划。实施严格采用 TDD：先运行能够证明缺口的失败测试，再完成对应实现；每个循环都必须服务于本设计规定的完整最终交付，不以临时拼装或功能缩水结束任务。

验证顺序：

1. 当前数据、训练、registry、推理、报告、历史和 PDF 专项基线；
2. 数据 manifest 和实际训练文件哈希；
3. 患者划分和泄漏审计；
4. 三个结局模型训练与评估；
5. 两个疾病阶段模型训练与评估；
6. 两种疾病关键指标趋势模型训练与评估；
7. artifact/metadata/evaluation 契约；
8. disease release set、原子切换和回退；
9. 双疾病在线推理和异常降级；
10. 新报告、数据库持久化、旧报告不变和 PDF；
11. 旧 progression API；
12. 前端类型检查、Node 合约和构建；
13. `git diff --check` 和保护范围；
14. 最后再评估全量 pytest，耗时过长可中止并如实记录。

必须覆盖：

- 脂肪肝和 AD 分别验收；
- 旧报告正文不变，新报告使用新模型组；
- 模型缺失、metadata 不匹配、artifact/evaluation 哈希错误、特征不兼容和推理异常；
- release set 切换失败不改变当前活动版本；
- 回退恢复上一版本；
- 旧 progression API 不受影响；
- PDF 与保存正文一致；
- 不泄露患者身份、秘密、绝对路径或 traceback。

## 18. 上线批准边界

实现和 candidate 验收完成后，向用户提交：

- 双疾病数据和划分摘要；
- 每类模型的开发验证与锁定测试结果；
- 旧基线与新模型对比；
- release set 文件清单和哈希；
- smoke、报告、历史、PDF、前端和旧 API 验证证据；
- 切换与回退步骤。

只有得到用户明确批准，才允许切换生产活动 release set 或更新相关正式数据。不会自动 commit、push 或上线。
