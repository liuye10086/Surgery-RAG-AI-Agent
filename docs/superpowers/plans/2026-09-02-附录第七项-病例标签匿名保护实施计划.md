# 附录第七项：病例标签匿名保护实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 为新病例建立后端自动生成、可读、唯一且不可变的匿名病例编号，并切断自由 `patient_label` 进入报告标题、历史列表、PDF、日志和模型输入的路径，同时兼容旧病例和旧报告读取。

**架构：** 在病例服务层集中生成 `CASE-XXXX-XXXX` 匿名编号，在 `operator_cases` 增加可空兼容字段和唯一约束。新写入只使用系统编号；旧 `patient_label` 保留用于历史兼容读取但不再作为新报告输出来源。报告、PDF、快照和前端显示统一读取匿名编号，训练特征继续排除所有身份字段。

**技术栈：** Python 3、FastAPI、Pydantic v2、SQLAlchemy、Alembic、PostgreSQL JSONB、pytest、Vue 3、TypeScript、Element Plus、Node 内置测试运行器、Vite。

## 全局约束

- 不连接、读取、迁移或修改生产数据库。
- 不提交、推送、重置或覆盖与本任务无关的改动。
- 不自动删除、清洗或批量改写历史病例、历史报告或训练数据。
- 新匿名编号固定使用 `CASE-XXXX-XXXX`；字符集排除 `I`、`O`、`1`、`0`。
- 操作者不能自定义匿名编号；客户端提交的旧 `patient_label` 不得覆盖系统编号。
- 匿名编号创建后不可修改；数据库内部主键不作为展示编号。
- 前端修改前必须遵守 `docs/DESIGN_SPEC.md`，继续使用既有暖杏蓝设计变量和组件规范。
- 计划、设计和新增文档说明使用中文；代码技术标识保持现有命名。
- 生产上线状态必须与仓库实现状态分开表述。

## 失败时的回滚与阻断方式

1. 任一 TDD 测试若因环境、依赖或数据库连接问题失败，先停止实现扩展，记录失败原因，不将环境失败误判为功能通过。
2. 匿名编号生成器若发生格式错误、随机源异常或唯一冲突超过 5 次，阻断病例创建，不降级为数据库主键或自由标签。
3. Alembic 迁移契约、ORM 字段或只读检查不一致时，不执行任何本地或生产迁移。
4. 历史数据兼容测试失败时，不自动回填、清洗、删除或改写历史数据；保留现状并报告阻断点。
5. 前端构建或契约测试失败时，不宣称实现完成；仅修复本任务涉及的 UI 和类型文件。
6. 如发现无关文件变化，先保留用户已有改动，停止清理性操作，报告准确文件清单。

## 验证完成标准

- 新病例由后端生成唯一、可读、不可变的 `CASE-XXXX-XXXX`；操作者无法自定义。
- 新病例和报告链路不再使用自由 `patient_label` 作为标题、文件名、日志或模型输入。
- `input_snapshot`、预测输入、报告正文、历史列表、详情和 PDF 遵守匿名边界。
- 旧病例、旧报告、导入数据和合成训练数据按设计兼容，不自动清理或改写。
- Alembic `0018`、ORM、只读检查和测试契约一致；生产数据库未连接、未迁移、未修改。
- 后端、脚本、前端测试和前端构建均有新鲜命令输出作为证据。
- `git diff --check` 通过，工作区无无关变更。
