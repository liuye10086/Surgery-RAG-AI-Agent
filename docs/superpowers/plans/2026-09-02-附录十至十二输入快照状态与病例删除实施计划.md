# 附录十至十二输入快照、报告状态与病例删除实施计划

> **给执行代理的要求：** 必须使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，按任务逐项执行。本计划中的步骤使用复选框跟踪。每个任务都必须先写失败测试，再写最小实现，最后运行该任务的专项测试。本计划不包含提交、推送或生产数据库操作。

**目标：** 为新纵向预测报告建立可验证的输入快照完整性标识和生成批次，保证报告生成状态在异常、取消、超时和并发条件下安全收敛，并明确病例删除后历史报告的保留、读取和权限边界。

**架构：** 新增一个无副作用的完整性服务，负责规范化、SHA-256 哈希和完整生成指纹。ai_reports 增加四个可空字段，由创建流程保存批次和输入哈希，由统一生成流程条件更新终态并保存完整指纹。病例继续硬删除，报告通过 ON DELETE SET NULL 解除病例关联，历史读取只依赖报告自身保存的数据。

**技术栈：** Python、FastAPI、SQLAlchemy、PostgreSQL JSONB、Alembic、Pydantic、pytest、Vue 3、TypeScript、Node.js 契约测试。

- [ ] **步骤 1：编写失败测试**

覆盖字典键顺序稳定、访视数组顺序保留、日期统一、数字稳定、哈希声明不参与自身哈希、修改快照/预测/正文可被检测、旧字段缺失返回不可验证。

示例：

```python
def test_snapshot_hash_is_stable_for_mapping_key_order():
    first = {"age": 60, "visits": [{"visit_date": "2024-01-01"}]}
    second = {"visits": [{"visit_date": "2024-01-01"}], "age": 60}
    assert compute_input_snapshot_sha256(first) == compute_input_snapshot_sha256(second)

def test_generation_fingerprint_detects_saved_content_change():
    fingerprint = create_generation_fingerprint(snapshot, prediction, "原始正文")
    result = verify_report_integrity(snapshot, snapshot_hash, fingerprint, prediction, "被修改正文")
    assert result.status == "invalid"
```

## 验收标准

- 新报告保存 input_snapshot_sha256、generation_batch_id 和一致的快照声明。
- 成功报告保存 generation_fingerprint，可检测快照、预测结果或正文被修改。
- 模型加载失败、运行异常、取消和超时均进入安全终态，错误阶段明确且不泄露内部细节。
- 已完成或已失败报告不会被并发流程覆盖。
- 病例删除后报告及快照、预测结果、正文和来源保留，关联置空，权限仍按原操作者隔离。
- 旧报告字段为空时继续只读兼容，不批量补写、不重算、不清洗历史数据。
- AD 和脂肪肝后端测试、前端契约、构建和结构检查通过。
- 核查文档只更新附录第 10、11、12 项，且明确仓库实现状态不等于生产上线。
